# Мониторинг конкурентов

Раздел работает внутри существующего кабинета
`https://test.lavka-speciy.com/analytics/`, с тем же входом. Веб-код совместим с PHP
7.3; проверки страниц выполняет отдельная команда PHP 8.2 CLI. Нужны уже имеющиеся
SQLite, cURL и DOM. Изменение тарифа, версии PHP магазина, DNS и платный сервис
для этого варианта не требуются.

## Что отслеживается

Поддерживаются четыре выбранных конкурента и публичные товарные страницы «Лавки».
Наблюдение ограничено добавленными страницами товаров, условий и каталога. Оно не
означает сплошной обход всех товаров магазинов. Активных товарных страниц может быть
до 300, всех страниц вместе — до 350. Несколько фасовок на одном URL не требуют
нескольких целей наблюдения.

Начальная выборка: 56 публичных страниц наших товаров и 70 приоритетных сочетаний
«товар — фасовка» из согласованного списка; одинаковые ID объединены. Добавлены
22 карточки возможных аналогов у четырёх конкурентов и 12 страниц условий и
ассортимента. Всего 90 целей наблюдения. Суммы продаж и число покупателей из
исходной таблицы в модуль не переносятся. Карточки конкурентов — предложения для
ручной проверки соответствия, без заранее сохранённых цен и наличия.

Для товара сохраняются найденные варианты, цена и прежняя цена, валюта, фасовка,
наличие и условия предложения. Цена за 100 г или 1 кг имеет смысл только при
известном весе и единице продажи. Вес нельзя подставлять из общего описания при
нескольких вариантах. Условная скидка за объём или минимальную сумму не становится
обычной ценой упаковки. Если извлечь поле надёжно нельзя, оно остаётся неизвестным.

Сравнение с нашими товарами требует ручного подтверждения соответствия: состав,
качество, обработка и фасовка могут различаться при похожем названии. Страницы
«Лавки» — отдельные публичные источники актуальных предложений. Исторические цены
заказов в аналитике не служат текущим прайсом магазина.

Чтобы включить разницу цен, открыть «Настроить» у нашей карточки, проверить группу
товара и подтвердить сопоставимость. Затем у карточки конкурента выбрать ту же
группу по названию нашего товара и подтвердить состав/сорт/обработку. Сравнение
появится после успешной свежей проверки обеих страниц, при известном весе, одной
валюте, наличии и обычной цене без дополнительных условий. Если доступно несколько
наших фасовок, приоритет имеет ровно одна фасовка того же веса; неоднозначная база
сравнения не выбирается автоматически. Миллиграммы в названии капсул и миллилитры
в названии масла не считаются массой упаковки.

Страницы условий сохраняются как датированные текстовые наблюдения с исходной
ссылкой: скидки, доставка, минимальный заказ и другие коммерческие условия могут
требовать ручного прочтения. Сведения, сообщённые пользователем, помечаются как
непроверенные, пока не подтверждены источником. Изменение текста страницы само по
себе не доказывает изменение конкретного тарифа доставки или скидки.

Для страниц каталога первое успешное чтение создаёт исходный список. Товар,
впервые замеченный при последующей проверке такой страницы, попадает в находки.
Это дата обнаружения на наблюдаемой странице, а не доказанная дата запуска товара.
Пагинация, перестановка карточек и неполное покрытие каталога требуют проверки.

У каждого наблюдения есть источник и время. Ошибка запроса, CAPTCHA, неизвестная
цена и отсутствие товара — разные состояния. При ошибке сохраняется предыдущий
успешный результат и показывается его возраст; цена не заменяется нулём. Первое
заполнение раздела не создаёт фиктивных цен и успешных проверок.

Работа извлечения данных со всех четырёх сайтов ещё не подтверждена успешными
запусками на рабочем хостинге. Доступность отдельных полей зависит от публичной
разметки сайта. Клиентский JavaScript и обход CAPTCHA не выполняются; 403, 429 и
ограничения robots.txt учитываются как ограничения источника.

Парсер использует JSON-LD, товарную микроразметку, явные данные вариантов и
метаданные цены/акции. Цена «от», неподписанная доплата опции или цена связанного
товара не заменяет цену нужной фасовки. Если сайт отдаёт варианты только через
JavaScript или изменил разметку, появится ошибка либо неизвестное поле; для такого
источника потребуется отдельная доработка по его фактической публичной разметке.

## Порядок обновления существующей установки

Выполнять в WebSSH ADM.TOOLS. Текущая установка и закрытые данные уже существуют;
пароль кабинета и `source.json` повторно не настраиваются. Сначала сделать закрытую
резервную копию текущей версии:

```bash
php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/backup.php \
  --data /home/lavkasp/lavka-speciy.com/analytics-private \
  --destination /home/lavkasp/lavka-speciy.com/analytics-backups
```

После успешной копии получить рабочую ветку поставки и обновить ресурсы кабинета:

```bash
git -C /home/lavkasp/lavka-speciy.com/analytics-app branch --show-current
git -C /home/lavkasp/lavka-speciy.com/analytics-app pull --ff-only
php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/deploy.php --refresh-assets \
  --shop-root /home/lavkasp/lavka-speciy.com/test \
  --webroot /home/lavkasp/lavka-speciy.com/test/analytics \
  --data /home/lavkasp/lavka-speciy.com/analytics-private \
  --url https://test.lavka-speciy.com/analytics
```

Вывод первой команды должен быть `analytics-demo`. Если ветка другая, остановить
обновление и проверить клон. После ошибки любой команды следующие не выполнять.
Публикация в Git сама по себе хостинг не обновляет. Публичная папка — именно
`test/analytics`, а не соседняя `analytics` прежнего поддомена.

Создать схему мониторинга отдельной идемпотентной командой:

```bash
php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/competitors.php \
  --init-only --data /home/lavkasp/lavka-speciy.com/analytics-private
```

Она создаёт закрытую `competitors.sqlite3` и начальные цели наблюдения. Существующие
цели и история сохраняются. `--init-only` не загружает сайты. `--refresh-assets`
сам не выполняет эту инициализацию и не регистрирует расписание.

Перезагрузить кабинет, в том числе на iPhone. Добавить или проверить конкретные
товарные URL и подтвердить сопоставления. У кнопки повторной проверки действие —
поставить цель в очередь. Открытие раздела и эта кнопка не запускают сетевой обход
в веб-запросе. Для первого короткого пакета выполнить:

```bash
php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/competitors.php \
  --data /home/lavkasp/lavka-speciy.com/analytics-private --limit 5 --seconds 45
```

Команда обрабатывает только подошедшие цели. При большем списке оставшиеся
дождутся следующего пакета. Нельзя судить об успехе всех сайтов по одной удачной
странице: проверять состояние и время каждой цели в кабинете.

## Отдельное расписание мониторинга

Плановый интервал каждой успешно прочитанной цели — 24 часа. Короткая задача
каждые 15 минут выбирает очередной небольшой пакет. Это не означает проверку
каждого товара каждые 15 минут. После ошибок применяются отложенные повторы.

Уточнить абсолютный путь к уже установленному PHP 8.2 CLI:

```bash
command -v php
php --version
```

В ADM.TOOLS создать **отдельную** задачу. Заменить `/ABS/PHP82` в примере результатом
`command -v php`, убедившись, что это PHP 8.2. Пути приложения и данных ниже точные.

```text
7,22,37,52 * * * * /ABS/PHP82 /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/competitors.php --data /home/lavkasp/lavka-speciy.com/analytics-private --limit 5 --seconds 45 >> /home/lavkasp/lavka-speciy.com/analytics-private/competitors-cron.log 2>&1
```

Сдвиг минут уменьшает совпадение со стандартным расписанием синхронизации заказов.
Существующую задачу `cron.php` сохранить. Новый runner использует собственную
блокировку `.competitors.lock`; повторный экземпляр не выполняет параллельный обход.
Бюджет времени проверяется между запросами: уже начатый запрос может завершиться
после этого порога в пределах своего таймаута. Фактическую нагрузку и журнал
проверить на хостинге; ограничение пакета можно уменьшить. Журнал находится в
закрытом каталоге, срок его хранения задаётся отдельно.

Для HTTP действует таймаут до 12 секунд на цепочку редиректов и предел ответа
2 МБ. Системное разрешение DNS имеет собственный таймаут. Разрешены только
публичные HTTPS-адреса выбранных магазинов; каждое перенаправление и его правила
robots.txt проверяются отдельно. Изменение магазина при редиректе запрещено.
Длинная пауза из robots.txt переносит цель на следующий запуск. Если окружение
задаёт исходящий HTTP-прокси, прямую привязку проверенного IP нельзя гарантировать:
runner возвращает понятную ошибку сетевой настройки и не обходит прокси.

Расписание не создаётся автоматически и не считается настроенным до проверки
панели и последующих запусков. Автоматических писем и сообщений модуль не отправляет.

## Хранение, резервные копии и проверки

Данные мониторинга находятся в
`/home/lavkasp/lavka-speciy.com/analytics-private/competitors.sqlite3`, вне публичных
папок. Они отделены от заказов, CRM, сессий и исходной MySQL. Не переносить эту БД,
рабочую аналитику и закрытые конфиги в Git, публичные архивы или браузерные тесты.
Полный HTML страниц в историю не записывается.

После обновления `bin/backup.php` включает `competitors.sqlite3`, если она есть,
вместе с основной аналитикой и прежними закрытыми конфигами. Каждая SQLite
копируется через Backup API или согласованный `VACUUM INTO`, проверяется
`quick_check` и получает права 600. Это отдельные согласованные снимки, их моменты
могут различаться. На старой установке без мониторинга резервное копирование
работает как прежде. Активные сессии не включаются. Ежедневное расписание копий
и удаление старых копий остаются отдельными задачами.

Перед публикацией проверять на синтетических данных:

- PHP 7.3 для общих файлов и веб-маршрутов; PHP 8.2 для runner.
- Вход и проверку origin новых маршрутов, отсутствие сетевых запросов в HTTP.
- Разные фасовки, валюты, условные скидки, неизвестный вес и ручное подтверждение
  сопоставлений; ошибку парсинга и сохранение предыдущей успешной цены.
- Начальный каталог без ложных новинок, последующее появление нового URL,
  историю условий с датой и ссылкой на источник.
- Запрет посторонних/внутренних адресов и редиректов, таймауты, CAPTCHA/403/429,
  robots.txt, блокировку перекрытия и ограничение числа страниц.
- Резервную копию с обеими SQLite, включая зафиксированные WAL-записи, права 600,
  отсутствие сессий; старую установку без БД конкурентов и отказ на повреждённой БД.
- Интерфейс на 390 CSS px: формы, фасовки, длинные URL, состояние ошибки и возраст
  данных; сохранность действующих разделов аналитики и CRM.

Успех тестов на HTML-фикстурах не подтверждает доступность сайта из хостинга.
После установки отдельно проверить первые реальные наблюдения и сведения на
самих страницах, прежде чем принимать ценовое решение.
