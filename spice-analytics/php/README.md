# Лавка · PHP-аналитика ocStore

Текущий план: сначала `https://test.lavka-speciy.com/analytics/`, затем при необходимости
папка `/analytics/` на основном домене. Существующая тестовая копия ocStore сохраняется.
Поддержан и отдельный поддомен. **Публичная установка и подключение живой БД пока не выполнены.**

## PHP магазина менять не нужно

На скриншоте ADM.TOOLS тестовый сайт использует PHP **7.3**, memory_limit **512M** и
копирует настройки с `www`. В SSH уже установлен PHP **8.2.33**. Сохраняем эту схему:

| Компонент | Исполнение |
|---|---|
| Витрина, админка и дополнения ocStore | Существующий веб-PHP 7.3 |
| Веб-кабинет аналитики | PHP 7.3+ в отдельной папке |
| Синхронизация MySQL и прогрев отчётов | Уже имеющийся PHP 8.2 CLI через cron |
| Настройка пароля, диагностические команды | Существующий PHP 8.2 CLI |

Не меняйте версию PHP сайта, encoder, open_basedir и копирование настроек ради установки.
PHP 8.2 CLI не переключает веб-версию; эта независимость описана
[хостингом](https://www.ukraine.com.ua/wiki/hosting/php/version/).
На стандартном PHP 7.3 драйвер MySQL не поддержал caching_sha2_password MySQL 8.4
(SQLSTATE/driver 2054). Поэтому синхронизация явно требует CLI 8.2; понижать способ
аутентификации БД или отключать TLS не нужно. Код веб-кабинета не открывает MySQL:
читает закрытую локальную SQLite, подготовленную cron.

Аналитика не подключает startup.php, index.php или дополнения магазина. Совместимость
конкретных установленных дополнений с PHP 8.2 не проверена: их файлов у нас нет.
Исходный дистрибутив ocStore сам по себе не доказывает совместимость всей сборки.
PHP 7.3 устарел и не поддерживается upstream; обновление магазина и дополнений следует
планировать отдельно с администратором, а не делать условием установки аналитики.

## Функции и данные

Все 12 экранов: календарь ISO-недель и количество покупок 2+/5+/10+, очередь контактов,
когорты, RFM, повторные продажи, товарные сочетания, фасовки/килограммы, сезонность,
география, GA4 CSV, обратимые объединения, настройки. BCMath сохраняет точность денег.
Суммы заказов не означают подтверждённые оплаты. Сообщения покупателям автоматически
не отправляются. В production HTTPS-кабинете имена и контакты видны после входа.

Сессии и пароль кабинета отделены от магазина. Argon2id, 12 часов, ограничение попыток,
проверка host/origin, Secure/HttpOnly/SameSite=Strict cookie. Для папки cookie
`lavka_analytics_session` имеет Path=/analytics/ и не задаёт Domain.
Папка на том же origin слабее изолирована от JavaScript магазина, чем отдельный поддомен;
Path cookie не является границей защиты от XSS. Рабочая БД, конфиги, кэш и копии
должны находиться вне **всех** публичных корней. В Git их нет.

## 1. Загрузить код и проверить веб-PHP без изменения настроек

По скриншотам `/home/lavkasp/lavka-speciy.com/` содержит отдельные публичные папки
`www`, `test`, `analytics` и хранилища. Предполагаемый корень тестового сайта —
`/home/lavkasp/lavka-speciy.com/test`. Подтвердите его в «Настройки сайта».
Код и данные ниже располагаются рядом, внутри разрешённого open_basedir домена,
но **вне** этих публичных папок. Папка `analytics` рядом с `www` относится к поддомену.

Через WebSSH; репозиторий публичный. Если `analytics-app` уже существует, не заменяйте
его вслепую: сначала проверьте содержимое. Новый clone откажется писать поверх него.

```sh
umask 077
git clone --depth 1 --single-branch --branch analytics-demo https://github.com/andrey-martyn/test1.git "$HOME/lavka-speciy.com/analytics-app"
cd "$HOME/lavka-speciy.com/analytics-app/spice-analytics/php"
php bin/preflight.php
php bin/check_web.php --webroot "$HOME/lavka-speciy.com/test" --url https://test.lavka-speciy.com
```

`check_web.php` создаёт новый случайно названный временный PHP-файл, защищённый случайным
токеном и сроком 120 секунд, обращается к нему по проверенному HTTPS и удаляет файл
при успехе или ошибке. Никаких phpinfo(), паролей, конфигов магазина или заказов
не выводится. Проверяются фактический веб-PHP, расширения, Argon2id, SQLite, HTTPS,
доступ к закрытому коду внутри open_basedir и память. Конфигурация сайта не меняется.
Если сертификат/домен недоступны или не хватает расширений — сначала исправляется
эта конкретная причина; проверка TLS не отключается.

Нужны в веб-PHP: pdo_sqlite, sqlite3, bcmath, mbstring, intl, openssl и Argon2id.
Для CLI синхронизации дополнительно нужен pdo_mysql. При SQLite без SQLite3::backup нужен SQLite 3.27+
для согласованного VACUUM INTO. Памяти 512M на скриншоте достаточно с запасом;
на живом хостинге проверяется фактический расход.

## 2. Установить отдельную папку

После успешной проверки, с подтверждёнными путями:

```sh
php bin/deploy.php --shop-root "$HOME/lavka-speciy.com/test" --webroot "$HOME/lavka-speciy.com/test/analytics" --data "$HOME/lavka-speciy.com/analytics-private" --url https://test.lavka-speciy.com/analytics
php bin/configure.php --data "$HOME/lavka-speciy.com/analytics-private" --password
php bin/configure.php --data "$HOME/lavka-speciy.com/analytics-private" --source
php bin/cron.php --data "$HOME/lavka-speciy.com/analytics-private"
```

Пароли вводятся скрыто в SSH, не через чат и не в аргументах. MySQL-пароль хранится
только в закрытом source.json с правами 600. Для входа хранится Argon2id-хеш;
повторная команда --password отзывает старые сессии. Каталоги данных 700, файлы 600.

Установщик отказывается писать в непустую папку, проверяет соответствие URL и пути,
размещение кода/данных вне **всего** корня сайта, включая разрешение родительских
symlink. В новую папку помещает только index.php, .htaccess, static/. Корневые
index.php/.htaccess/config.php OpenCart сохраняются. API/вход используют существующий
`/analytics/index.php?route=...`, чтобы стандартные SEO-правила OpenCart !-f/!-d не
перехватывали запросы. Настоящие правила хостинга и публичный HTTPS проверяются отдельно.

Для установки прямо в корень test сначала сохраняют существующие файлы/конфигурацию
и назначают кабинету отдельный пустой корень через панель; текущую копию не удаляют.
Для отдельного поддомена нужны DNS и сертификат; --shop-root не требуется при URL без пути.
Веб-PHP и дополнения основного магазина остаются без изменений во всех этих вариантах.

## 3. MySQL и расписание

Отдельный пользователь SELECT-only на oc_order, oc_order_product, oc_order_option,
oc_order_total, oc_order_history, oc_order_status. Не нужны INSERT/UPDATE/DELETE/DDL,
oc_customer, административные сессии, пароли клиентов, платёжные реквизиты и строки улиц.
Берутся имя, контакты, населённый пункт/регион/страна, IP, суммы, товары и выбранные опции.
Префикс таблиц настраивается. Исходная БД никогда не изменяется приложением.

Удалённая MySQL — только проверяемый TLS с CA и именем сервера. Также поддержаны
локальный сокет/loopback защищённого SSH-туннеля. Не отключайте проверку сертификата.
InnoDB читается в consistent read-only snapshot. MyISAM — два совпавших полных чтения
с паузой и повторами; это проверка стабильности, не транзакционная гарантия.
Правки старых заказов, удаления и изменения дочерних строк также обнаруживаются.
Замена локальных записей транзакционная, сохраняет CRM/настройки/ручные связи/GA4.
Ошибки оставляют прошлые данные; последний успех/ошибка видны в кабинете.

Начальный cron — каждые 15 минут, с настоящими абсолютными путями к **PHP 8.2 CLI**
(уточнить command -v php) и файлам. Пример структуры команды:

```text
*/15 * * * * /ABS/PHP82 /ABS/lavka-speciy.com/analytics-app/spice-analytics/php/bin/cron.php --data /ABS/lavka-speciy.com/analytics-private >> /ABS/lavka-speciy.com/analytics-private/cron.log 2>&1
```

Cron исключает перекрытие задач и прогревает текущие отчёты для двух последних лет.
Кэш ограничен 32 отчётами, изменения CRM/данных отзывают его. Вкладка проверяет
обновления раз в минуту и сохраняет открытую редактируемую карточку. Сначала измерьте
нагрузку CPU/RAM/БД на тарифе; при достаточном запасе можно уменьшить интервал до 5 минут.
Сам выбор папки или поддомена не меняет общие лимиты хостинг-аккаунта.

## География, GA4 и резервные копии

IP не отправляются внешним API. Нужен отдельный легальный City MMDB; официальный
MaxMind reader 1.14.0 включён с лицензией и provenance. Тестовая MMDB служит только
для тестов и не подходит для географии покупателей. Реальная геобаза ещё не установлена.
GA4 — импорт CSV и сопоставление transaction_id=order_id; аккаунт и живые отчёты не подключены.

```sh
php bin/import_geoip.php --data "$HOME/lavka-speciy.com/analytics-private" --file /PRIVATE/geoip-city.mmdb.gz
php bin/backup.php --data "$HOME/lavka-speciy.com/analytics-private" --destination "$HOME/lavka-speciy.com/analytics-backups"
```

Копия — SQLite Backup API на новом PHP, согласованный VACUUM INTO на PHP 7.3,
с проверкой quick_check; включает CRM/закрытые конфиги, исключает активные сессии.
Проверка публичных путей выполняется до mkdir/chmod. Ежедневный cron и хранение
копий настраиваются отдельно; автоматического удаления старых копий нет.

## Проверено в песочнице

На настоящих PHP 7.3.33 и 8.2: бизнес-правила, Argon2id/вход/выход/лимиты, все
12 экранов, CRM/GA4, карты/мобильный вид. Все поля отчётов 2026, 2025, начала 2021
совпали с эталоном на 4917 заказах/34510 товарных строках. В PHP 7.3 добавлены
стабильные сортировки и fallback имени Europe/Kiev для старой tzdb; отчёт использует
киевское время. В sandbox PHP 7.3: первый расчёт около 1 с, кэш 0.03 с, пик 125 МБ;
это не обещание скорости на хостинге.

Проверена связка PHP 8.2 CLI → HTTPS → PHP 7.3 веб-проверка с настоящей проверкой
сертификата и удалением временного файла при успехе/ошибке TLS. MySQL 8.4 проверяется
на синтетической БД через CLI 8.2: SELECT-only, MyISAM/InnoDB, изменения/удаления,
сохранение CRM, проверяемый TLS. PHP 7.3 CLI для этой синхронизации не поддерживается;
проверка с современным способом аутентификации выявила код ошибки 2054.

Docker и Python нужны только для разработки/проверок. Runtime включает только PHP,
frontend и локальный GeoIP reader. Образы разработки закреплены digest; PHP 7.3
использует подписанные пакеты ICU 67.1-7 из основной Bullseye-ветки, поскольку security
индекс в прокси ссылался на недоступные .deb. TLS/подписи пакетов не отключались.
Никакого Docker, Python, Composer или платного Python-хостинга на сервере не нужно.
