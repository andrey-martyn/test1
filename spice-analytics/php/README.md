# Лавка · PHP-версия

Закрытая аналитика ocStore 3.0.2.0 для обычного PHP-хостинга, без Python, Docker
или отдельного сервера в эксплуатации. Текущий вариант размещения — папка
`https://lavka-speciy.com/analytics/` (или `www`, если магазин перенаправляет на него)
на существующем тарифе «Быстрый» в ADM.TOOLS. Дополнительно поддержан отдельный поддомен.
DNS домена обслуживает Cloudflare, доступа к нему у пользователя нет; для папки
новая DNS-запись не нужна. **Публикация и подключение к живой БД ещё не выполнены**.

PHP 8.2 и необходимые расширения подтверждены выводом WebSSH: `pdo_mysql`,
`pdo_sqlite`, `bcmath`, `mbstring`, `intl`, `openssl`, `sqlite3`. Для входа нужен
Argon2id; это дополнительно проверяет `php bin/preflight.php`. Версию основного
магазина не меняем. PHP в SSH и PHP веб-сайта могут различаться — подтверждён только
CLI. Нужен PHP 8.2+ именно для папки кабинета. Если магазин использует более старую
версию, сначала уточните у поддержки штатную настройку отдельного PHP-обработчика
для папки на вашем тарифе. Не вставляйте угаданные AddHandler/SetHandler и не меняйте
PHP всей витрины. Рекомендуемый `memory_limit` кабинета — 256M с запасом.

Хостинг описывает независимость веб-версии от CLI в
[официальной инструкции](https://www.ukraine.com.ua/wiki/hosting/php/version/).
Возможность отдельного обработчика для папки на этом аккаунте ещё не подтверждена.

## Что сохранено

Все 12 экранов: календарь и диапазоны количества покупок, очередь контактов,
когорты, RFM, повторные продажи и сочетания товаров, фасовки/килограммы, сезонность,
география, GA4 CSV, обратимые объединения, настройки. Денежные вычисления — BCMath.
CRM хранится отдельно от магазина. После входа на боевом HTTPS-адресе имена видны.
Кнопка скрытия остаётся. Никакие сообщения покупателям автоматически не отправляются.

SQLite, конфиги, пароль и кэш находятся **вне всех публичных каталогов**. В Git и
архив включён только код и обезличенное демо. Из исходного заказа загружаются имя,
контакты, город/область/страна, IP, суммы и строки товаров; пароли покупателей,
учётки администраторов, платёжные реквизиты и сессии магазина не запрашиваются.

## Установка через WebSSH

Репозиторий публичный; пароль GitHub для clone не нужен. Если каталог уже существует,
не запускайте повторный clone поверх него — сначала проверьте его содержимое.

```sh
git clone --branch analytics-demo --single-branch https://github.com/andrey-martyn/test1.git "$HOME/analytics-app"
cd "$HOME/analytics-app/spice-analytics/php"
php bin/preflight.php
```

### Вариант 1: папка магазина без нового DNS

По скриншоту `/home/lavkasp/lavka-speciy.com/` содержит отдельные каталоги
`www`, `analytics`, `test`. Существующая папка `analytics` рядом с `www` относится
к поддомену. Для URL `/analytics/` нужна **папка внутри публичного корня магазина**.
Ниже предполагается `/home/lavkasp/lavka-speciy.com/www`; подтвердите этот путь
в настройках основного сайта. Используйте канонический HTTPS-хост магазина
(`www` или без него), чтобы его перенаправления не мешали кабинету.

После подтверждения веб-версии PHP и путей:

```sh
php bin/deploy.php --shop-root /home/lavkasp/lavka-speciy.com/www --webroot /home/lavkasp/lavka-speciy.com/www/analytics --data "$HOME/analytics-private" --url https://lavka-speciy.com/analytics
```

Это создаёт только новую пустую папку. Установщик откажется изменять непустую папку,
неверное соответствие URL/путей, размещение кода или данных внутри **всего** публичного
корня магазина. Корневые `index.php`, `.htaccess`, конфиг ocStore не меняются.
Не копируйте исходники проекта или ZIP целиком в `www`.

Запросы кабинета идут через существующий `/analytics/index.php?route=...`:
стандартные SEO-правила OpenCart с проверками `!-f`/`!-d` не забирают их в витрину.
HTML/CSS/JS/карты и переходы также учитывают папку. Cookie
`lavka_analytics_session` ограничена путём `/analytics/`, отдельная от сессии ocStore.
Папка и поддомен используют одинаковые расчёты и функции; общие CPU/RAM/БД остаются
ограничением тарифа в обоих случаях. Размещение в одном origin не изолирует кабинет
от уязвимостей JavaScript магазина так, как отдельный поддомен; одного Path cookie
для такой изоляции недостаточно. Доступ всё равно защищён отдельным паролем.

### Вариант 2: отдельный поддомен

Потребуются A-запись в Cloudflare и сертификат. В настройках **поддомена** выберите
PHP 8.2 и включите перечисленные расширения. Узнайте назначенный ему полный
document root; это отдельная папка, а не корень магазина.

```sh
php bin/deploy.php --webroot '/ПОЛНЫЙ/ПУТЬ/ИЗ/ПАНЕЛИ' --data "$HOME/analytics-private" --url https://analytics.lavka-speciy.com
```

### Общие шаги после установки файлов

```sh
php bin/configure.php --data "$HOME/analytics-private" --password
php bin/configure.php --data "$HOME/analytics-private" --source
php bin/cron.php --data "$HOME/analytics-private"
```

Пароли вводятся скрыто через SSH; не передавайте их в чат или аргументы команд.
Для кабинета создаётся Argon2id-хеш, исходный пароль не сохраняется. MySQL-пароль
отдельного пользователя нужен соединению и сохраняется только в закрытом `source.json`
с правами 600. Для повторной смены пароля используйте ту же команду `--password`:
все старые сессии станут недействительными.

В документ root установщик помещает только маленький `index.php`, `.htaccess`
и `static/`. Код `src/`, команды `bin/`, рабочая база, кэш и ключи остаются в закрытых
папках. Включите сертификат и HTTP→HTTPS в панели. Действительный сертификат и
реальную доступность адреса необходимо проверить отдельно после установки.

## MySQL и cron

Отдельный пользователь: **SELECT только** на `oc_order`, `oc_order_product`,
`oc_order_option`, `oc_order_total`, `oc_order_history`, `oc_order_status`.
Префикс настраивается. Не нужны права INSERT/UPDATE/DELETE/DDL, доступ к `oc_customer`
или открытие MySQL всему Интернету. Для удалённой БД обязательны проверяемые TLS,
CA и имя сервера. При несовместимом TLS нужен предоставленный хостингом CA, локальный
сокет или защищённый SSH-туннель; проверки сертификата не отключаются.

В расписании ADM.TOOLS, сначала каждые пятнадцать минут, с **настоящими абсолютными путями**:

```text
*/15 * * * * /ПУТЬ/К/PHP82 /ABS/analytics-app/spice-analytics/php/bin/cron.php --data /ABS/analytics-private >> /ABS/analytics-private/cron.log 2>&1
```

PHP CLI и веб-версия должны быть 8.2+. Первый путь уточняется командой `command -v php`.
В cron нельзя полагаться на текущую папку или экспорт переменных в старом терминале.

Полная сверка обнаруживает правки/удаления, включая старые строки товаров без изменения
`date_modified`. InnoDB читается в consistent read-only snapshot. У MyISAM нет таких
транзакций: сверяются два полных чтения с паузой, при изменениях — до трёх попыток.
Это проверка стабильности, не строгая транзакционная гарантия. Магазин не блокируется.
Неустойчивый/неполный снимок и ошибки подключения сохраняют предыдущие данные.

Замена локальных записей и контрольной точки происходит одной транзакцией. CRM,
настройки, ручные связи и GA4 сохраняются. Пересекающиеся cron-задачи исключены.
Последний успех/ошибка показаны в интерфейсе. Cron заранее готовит текущие отчёты
для двух последних лет; изменения CRM/правил отзывают кэш сразу. Вкладка проверяет
новые данные раз в минуту и не перерисовывает открытую редактируемую карточку.

На живом хостинге замерьте длительность и нагрузку в панели. Если лимиты тарифа
позволяют и нужна более частая актуализация, интервал можно уменьшить до пяти минут.
Первое подключение должно быть
проверено по новому настоящему заказу и изменению статуса, не по старой выгрузке.

## География и GA4

Адрес доставки доступен сразу. Для IP нужен настоящий файл City MMDB. Официальный
MaxMind PHP reader 1.14.0 включён с лицензией и provenance; Composer на хостинге
не требуется. Установка отдельной легальной базы:

```sh
php bin/import_geoip.php --data "$HOME/analytics-private" --file /закрытый/путь/geoip-city.mmdb.gz
```

Никакие IP покупателей не передаются внешним API. Положение по IP приблизительное,
не адрес доставки; неизвестные места не подменяются выдуманными регионами. Настоящая
геобаза в песочницу пока не установлена: её официальный источник блокировал прокси.
GA4 работает через CSV из закрытого кабинета; живой GA4-аккаунт не подключён.

## Копии и проверка

```sh
php bin/backup.php --data "$HOME/analytics-private" --destination "$HOME/analytics-backups"
```

Копия делается SQLite Backup API, проверяется `quick_check`, включает CRM и закрытые
конфиги, исключает действующие сессии. Папка копий должна быть вне document root.
Ежедневный cron и срок хранения настраиваются отдельно с учётом свободного места.
Команда автоматически старые копии не удаляет.

Вход — HTTPS, Secure/HttpOnly/SameSite=Strict cookie с отдельным именем и путём,
12 часов, постоянный лимит
попыток, проверка host/origin, no-store/noindex. Кэш ограничен 32 отчётами, файлы 600.
После выкладки проверить анонимный запрет API, реальные имена после входа, новый
заказ, смену статуса, сохранение CRM после cron, выход и резервную копию. Витрина
и оформление заказов магазина должны продолжать работать.

## Проверено в песочнице

На 4 917 заказах и 34 510 товарных строках все поля отчётов совпали с эталонной
версией за 2026, 2025 и начало 2021 года. После оптимизации: первый расчёт
1,3–1,6 с, чтение кэша 0,05–0,10 с, пик ~112–114 МБ. Это замер в песочнице,
не обещание скорости на сервере магазина. Текущий объём подходит для PHP и SQLite;
при значительном росте/многих одновременных операторах пересматривается хранение
и состав расчётов. Ограничения сейчас прежде всего у тарифа CPU/RAM и актуальности cron.

Браузерная проверка всех экранов, фильтров, CRM/GA4, карт и мобильного вида прошла.
В режиме папки дополнительно проверены все 12 экранов, отсутствие запросов вне
`/analytics/`, вход/выход, область cookie и API. Генерируемый установщиком лаунчер
проверяется за имитацией стандартного SEO-правила OpenCart: витрина и исходные файлы
сохранены, публичные копии/данные через symlink отвергаются. Это локальная проверка,
не подтверждение конфигурации Apache/PHP и настоящего TLS на хостинге.
Синхронизация проверена на настоящем изолированном MySQL 8.4 с синтетическими данными:
SELECT-only, MyISAM/InnoDB, старые изменения, удаления, сохранение CRM и проверяемый TLS.
Проверки разработки находятся в `tests/` репозитория; Python/Docker там — только
для сравнительных тестов, в PHP-продукте они не используются.
