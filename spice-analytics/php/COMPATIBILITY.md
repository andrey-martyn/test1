# Проверка совместимости без изменения PHP магазина

Решение: оставить существующий веб-PHP **7.3** и копирование его настроек с `www`
на `test`. Для cron использовать **уже установленный PHP 8.2.33 CLI**. Это две
разные настройки, а не обновление PHP всего хостинга.

В исходной аналитике требование PHP 8.2 было нашим ограничением. Его убрали из
веб-части: заменили новые конструкции языка, добавили локальные функции совместимости,
стабильную сортировку равных значений и старое имя Europe/Kiev для tzdb PHP 7.3.
Расчёты, состав заказов и функции сохранены. Сам ocStore и его дополнения не изменялись.

| Проверка | PHP 7.3 веб | PHP 8.2 CLI |
|---|---|---|
| Все 12 экранов, фильтры, CRM/GA4, карты, мобильный вид | Пройдено | Совместимость также проверена |
| Все поля отчётов 2026, 2025, начала 2021 | Совпали с эталоном | Совпали с эталоном |
| Вход, выход, лимиты, Secure cookie | Пройдено, включая пароль из CLI 8.2 | Argon2id-хеш совместим |
| Резервная копия и целостность CRM | VACUUM INTO, пройдено | SQLite Backup API, пройдено |
| MySQL 8.4, SELECT-only, правки/удаления, MyISAM/InnoDB, TLS | Не поддерживаем для cron: драйвер отказал с кодом 2054 | Пройдено |
| HTTPS-проверка фактической веб-среды и удаление временного файла | Пройдено на тестовом HTTPS-стенде | Запускается из CLI 8.2 |

Модернизировать или ослаблять аутентификацию MySQL ради старого драйвера не требуется.
Веб-кабинет читает локальную SQLite, которую обновляет CLI 8.2.

Проверен исходный тег `3.0.2.0` официального репозитория ocStore
(commit `a1d7bc1e6434b8741e8a819238a2bf4e428194fb`). В его
[composer.json](https://github.com/ocStore/ocStore/blob/a1d7bc1e6434b8741e8a819238a2bf4e428194fb/composer.json)
указано минимальное `php >=5.4.0`; это не подтверждает совместимость с PHP 8.2.
Файлы конкретного магазина, его модификации, тема и дополнения у нас отсутствуют.
Поэтому проверка всех установленных дополнений на новом PHP **не выполнена**.
Повышать версию магазина без их отдельной проверки оснований нет.

PHP 7.3 больше не поддерживается upstream. Обновление самого магазина следует
планировать отдельно с администратором и проверять на копии. Установка аналитики
не требует делать это сейчас. Будущая нативная интеграция в ocStore — отдельный этап;
веб-кабинет в папке уже совместим с его текущей версией PHP.

Пока это результаты песочницы. На хостинге осталось проверить реальный HTTPS,
расширения/Argon2id/SQLite в веб-PHP и open_basedir, затем подключить SELECT-пользователя
и проверить новый настоящий заказ. `check_web.php` делает первую проверку без
изменения версии PHP, encoder, конфигурации и существующих файлов магазина.
