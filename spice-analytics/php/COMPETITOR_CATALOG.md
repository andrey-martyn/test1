# Свои цены из каталога ocStore

Отдельный импорт читает текущие цены выбранных товаров непосредственно из БД
ocStore. Сам импорт не меняет цены магазина, права MySQL, `source.json`, заказы,
CRM, сессии или таблицы мониторинга. Для нового этапа подготовлена отдельная
песочница **`lavkasp_test`** с пользователем **`lavkasp_sandbox`** и закрытым
каталогом **`analytics-private-test`**. Порядок создания пользователя, проверки
изоляции и переключения всего кабинета — [SANDBOX.md](SANDBOX.md).
Старый боевой источник не перенастраивается. Пароль в чат не передавать.

## Что получает отчёт

Снимок `own-catalog.json` хранится в существующем закрытом каталоге с правами 600.
В нём только выбранные активные товары «Лавки специй» с числовым `product_id` в
существующих ссылках мониторинга. По умолчанию читается выбранный список. После явного включения полного режима
подключается весь активный ассортимент магазина 0; данные покупателей не читаются.
Снимок отделён от `analytics.sqlite3` и `competitors.sqlite3`.

Успешный результат имеет `state: ok`, `last_success`, `checked_at`, `products`.
В песочнице также обязательны `source_database: lavkasp_test` и
`environment: sandbox`; снимок другого источника не используется как текущая цена.
Каждый товар содержит `target_id`, `product_id`/`source_product_id`, название,
модель, ссылку и `offers`. У предложения есть точный вес `grams`, название фасовки,
цена витрины строкой, UAH, наличие, время и `provenance`: ID товара, опции и
значения, база цены, поправка опции и вид базы (`base`, `special`,
`discount_quantity_1`). `provenance.raw_price` сохраняет точную сумму базы и
поправки с четырьмя знаками; `currency_decimal_places` указывает точность вывода.
Неизвестная фасовка или неподдерживаемая формула дают предупреждение и не создают
цену. Свободная строка фасовок из списка продаж не является доказательством веса.

При ошибке прошлый успешный снимок сохраняется; `own-catalog-status.json` сообщает
`state: error` и безопасный код без текста драйвера. Такой результат не участвует
в определении лидера. Успешный снимок старше 48 часов получает `state: stale`.

## Модель цены и границы

Поддерживается стандартная модель ocStore 3 для гостевой группы магазина 0:

1. Текущая базовая цена товара; активная скидка на одну упаковку, если она есть.
2. Активная акция для той же гостевой группы с приоритетом и ценой, как в ocStore.
3. Поправка `+`/`-` **конкретного** значения опции фасовки. Нулевая база допустима,
   если итоговая цена выбранной упаковки положительна.

Оптовые скидки от количества больше 1 и цены других групп не используются.
Берётся одна группа фасовок типа select/radio/image. Дополнительные обязательные
опции, несколько групп фасовок, нестандартные префиксы и неизвестный вес исключают
цену. Если опций нет, вес можно взять из однозначного свежего названия товара в
`product_description`; старые подписи из аналитики для этого не используются.
Миллиграммы действующего вещества и миллилитры не переводятся в граммы.

Проверяются статус товара, принадлежность магазину 0, дата доступности, минимальное
количество и остаток выбранной опции. Отсутствие товара не считается ошибкой чтения.
Поддерживается активная UAH с курсом 1 и точностью вывода 0 или 2 знака.
В этой установке подтверждён `decimal_place=0`: витрина показывает целые гривны.
Точная сумма базы и поправки сохраняется отдельно, а для сравнения округляется
один раз по точности валюты, как в стандартном
[ocStore 3.0.2.0](https://github.com/ocStore/ocStore/blob/v3.0.2.0/upload/system/library/cart/currency.php).
Например, `100,49 + 25,49 = 125,98`: на витрине это 126 грн.
Суммировать отдельно округлённые части нельзя. Импорт не меняет точность валюты
или исходные цены. Если магазин
включает налоги и у товара есть налоговый класс, предложение исключается с
`tax_unresolved`: географию налога угадывать нельзя. Сторонние модули цен,
персональные скидки, купоны и лояльность потребуют отдельной сверки с тестовой
витриной. До такой сверки импорт нельзя считать подтверждением всех её модификаций.

Все запросы к источнику — SELECT; для согласованности используются read-only
транзакция и две одинаковые сортированные выборки. Это также обнаруживает обычное
изменение MyISAM между чтениями. Изменившийся набор не заменяет прошлый снимок;
две равные выборки не являются транзакционной гарантией MyISAM. Бюджет проверяется
между запросами (30 секунд); уже начатый запрос ограничен таймаутом MySQL-клиента.

## Права чтения каталога

Пользователь песочницы читает шесть таблиц заказов и следующие объекты каталога
с префиксом `oc_` только в `lavkasp_test`:

- `oc_product`, `oc_product_to_store`, `oc_product_description`;
- `oc_product_option`, `oc_product_option_value`, `oc_option`,
  `oc_option_value_description`;
- `oc_product_discount`, `oc_product_special`;
- `oc_currency`, `oc_language`;
- ограниченное представление **`oc_analytics_catalog_settings`**.

Код не читает `oc_setting` напрямую: только фиксированное представление с четырьмя
разрешёнными ключами. Его SQL приведён в [SANDBOX.md](SANDBOX.md), рядом со вторым
представлением `oc_analytics_sandbox_guard`, проверяющим изоляцию таблиц записи.
Оба создаёт существующий администратор тестовой БД `lavkasp_test`; приложение
не выполняет DDL. В панели можно выдать SELECT + UPDATE на `lavkasp_test.*` либо
ограничить UPDATE тремя колонками цен, как описано в этой инструкции. Боевой
пользователь `lavkasp_analytics` и его шесть SELECT остаются прежними.

Полный список фиксированных полей и объектов можно вывести без подключения к БД
и без чтения настроек соединения:

```bash
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/sync_competitor_catalog.php --requirements
```

Если хостинг ограничивает создание представлений, подготовить их через
администратора хостинга. Отсутствие проверочного представления блокирует
подготовку песочницы и запись цен.

## Первое включение после подключения тестовой БД

После подготовки отдельного тестового источника выполнить один раз в WebSSH:

```bash
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/spice-analytics/php/bin/sync_competitor_catalog.php --data /home/lavkasp/lavka-speciy.com/analytics-private-test
```

Команда использует новый закрытый `source.json` песочницы; параметры соединения
и пароль не печатает. Выводит только статус, время и количество товаров/фасовок.
Неуспех сохраняет прежние цены и выдаёт код вроде `catalog_select_required`,
`catalog_read_failed`, `catalog_settings_missing`, `catalog_currency_unsupported`.

До первого успешного ручного импорта фоновая функция `sync_due` не открывает
`source.json` и не подключается к MySQL. После успешного импорта существующий runner
может обновлять снимок не чаще раза в сутки; новая задача cron не нужна. Это
включает только чтение. В песочнице все собственные товарные страницы исключаются
из HTTP-обхода, включая SEO-ссылки без ID. Для них требуется сопоставить числовой
ID тестового товара; старая цена боевого сайта не подставляется.

Запись тестовых цен выполняет отдельный модуль по явно просмотренному серверному
плану через локальную очередь и отдельный CLI-обработчик PHP 8.2, запускаемый
раз в минуту. Веб-PHP MySQL не открывает; импорт каталога сам UPDATE не делает.
После записи создаётся новый снимок
цен для отчёта. Формулы и ограничения — [PRICING_RULES.md](PRICING_RULES.md),
сценарий подтверждения и отката — [COMPETITOR_REPORT.md](COMPETITOR_REPORT.md).

## Режим всего ассортимента

`bin/prepare_monitoring.php` под PHP 8.2 CLI включает полный режим и выполняет
импорт из существующего источника. Фиксированные SELECT по product,
product_to_store и product_description регистрируют отсутствующие карточки;
затем прежняя проверенная модель цен читает все включённые ID. Повторный запуск
идемпотентен; пользовательские отключения сохраняются. Флаг режима и снимок
хранятся вне webroot. Настройки подключения и цены магазина не меняются.
Предельное число собственных активных товаров при расширении — 4000, общий
лимит мониторинга — 5000 товарных страниц; фактический ассортимент 400 укладывается.
Полная инструкция запуска и cron — [COMPETITORS.md](COMPETITORS.md).
