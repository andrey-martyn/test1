# Лавка · локальная аналитика ocStore

**Для боевого запуска на тарифе «Быстрый» выбрана полная PHP-версия:**
[php/README.md](php/README.md). Она работает без Python и без доплаты за Python-хостинг.
Публичный запуск и живая БД проверяются отдельно. Этот документ ниже описывает исходный
Python-прототип, оставленный как эталон расчётов и средство сравнительного тестирования.
PHP-кабинет поддерживает веб-PHP 7.3 и папку `/analytics/` без новой DNS-записи.
Синхронизация запускается уже установленным PHP 8.2 CLI; версия PHP витрины не меняется.
Установка в `test.lavka-speciy.com/analytics/` сохраняет тестовую копию ocStore.
В PHP-версии доступны вся история и календарные годы, сравнение сезонности годов,
контекстная справка и пакетное объединение выбранных пар контактов. Для обновления
существующего кабинета используйте режим `--refresh-assets` из PHP-инструкции.
Очередь контактов включает журнал реактивации, чеклист, ценность покупателей,
запрос для ручной работы в ChatGPT и отслеживание новых заказов после общения.

Прототип на реальной SQL-выгрузке: покупатели по неделям ISO, состав каждого заказа,
фасовки, напоминания о повторной покупке, обратимые ручные объединения и карта областей.
Магазин не изменяется. Исходный SQL не выполняется: импортёр читает только литералы
INSERT шести разрешённых таблиц и записывает их параметризованными запросами в SQLite.

## Быстро посмотреть

Откройте `lavka-demo.html` в браузере двойным щелчком. Это автономный снимок предыдущего прототипа за 2026 год (новые функции поставляются в PHP-кабинете),
на дату проверки 20 октября 2026. Имена заменены, email и телефоны удалены; IP и улицы
не включены. Работают фильтры покупателей, календарь, карточки и составы заказов,
фасовки, карта и CSV. Правила, периоды и объединения в этой копии доступны для просмотра.

## Запуск полной версии на компьютере

Нужен Python 3.11 или новее. Распакуйте проект, откройте терминал в этой папке.
Команды ниже одинаковы для Windows/macOS/Linux, если `python` запускает Python 3.

```sh
python -m venv .venv
```

Активируйте окружение:

```sh
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Windows cmd
.venv\Scripts\activate.bat
# macOS/Linux
source .venv/bin/activate
```

Далее выполните:

```sh
python -m pip install -r requirements.txt
python import_dump.py /полный/путь/к/lavkasp_test.sql
python app.py --init-password
python app.py
```

При инициализации задайте собственный пароль длиной от 12 символов. Он вводится скрыто;
на диске сохраняются только соль и scrypt-хеш. После запуска откройте в браузере
адрес 127.0.0.1, порт 8000. Приложение слушает только локальный интерфейс.
Остановка — Ctrl+C. Для следующего запуска достаточно `python app.py` в активном окружении.
Для изменения пароля остановите сервер и повторите `python app.py --init-password`.

`data/analytics.sqlite3` содержит персональные данные. Они не входят в исходный архив.
Файл выгрузки также не включён в архив исходников. Не размещайте эту папку в публичном
каталоге веб-сервера. Приложение уже требует вход; для будущего размещения в сети нужны
HTTPS, резервное копирование и согласованная схема доступа. В сеть прототип не опубликован.

## Повторная загрузка

Остановите сервер, выполните `python import_dump.py /путь/новая_полная_выгрузка.sql`
и снова `python app.py`. Импорт транзакционный: неполная выгрузка не заменяет базу.
Повтор той же выгрузки не удваивает заказы. Настройки и ручные связи сохраняются.
Это полная замена снимка; отдельные дельта-файлы для этого импортёра не подходят.
Перед обновлением своей рабочей копии можно сохранить резервную копию SQLite при
остановленном сервере. Для смены магазина используйте отдельную папку `data`.

## Правила расчётов

- По умолчанию исключены статус 0, отмены, возвраты и другие отрицательные статусы.
  В данной выгрузке используются 2 («В обработке»), 3 («Доставлено») и 0.
  Суммы нельзя считать подтверждённой оплатой. Правила статусов меняются в кабинете.
- Денежные вычисления используют Decimal; суммы переводятся в валюту конкретного
  заказа по сохранённому `currency_value`. Валюты в отчёте не смешиваются.
- Итог заказа берётся из `oc_order.total`. Суммы товаров — из `oc_order_product.total`:
  скидки на весь заказ, доставка и налоги из итогов могут давать отличие.
- Период — год ISO-недель, включая неделю 53. «Всего» в карточке — вся подходящая
  история до даты проверки. Будущие заказы не участвуют. Даты магазина считаются
  местными (Europe/Kyiv); часовой пояс исходной БД ещё нужно подтвердить.
- Отчёт на прошлую дату применяет статусы из текущего снимка, а не восстанавливает
  состояние оплаты на эту дату. Точная историческая финансовая отчётность не реализована.
- Напоминания: базовые 30 дней; после 3 разных дат покупок — медиана последних
  6 положительных интервалов. Первые 7 дней задержки — «Пора», затем «Просрочено».
  Настройки доступны в интерфейсе. По умолчанию очередь требует минимум две покупки; разовые покупатели доступны в отдельных сегментах;
  это сигнал для проверки, не команда на автоматическую рассылку.
- Автоматические связи: один ненулевой customer_id или совпадающая нормализованная
  пара email + телефон. Отдельные совпадения email, телефона или полного имени —
  кандидаты для проверки. Пустые контакты и служебные email `nomail` не объединяют гостей.
  Ручное объединение можно отменить в карточке. Исходные записи не переписываются.
- Вес берётся только из выбранной опции «Фасовка». `1 шт.` не переводится в граммы.
  Повторные покупатели товара считаются по разным заказам в выбранном периоде.
- Карта — область доставки, затем оплаты. Названия городов сохраняются из заказов:
  Одеса/Одесса пока могут отображаться отдельными строками. Неизвестные регионы
  показаны в таблице, без придуманной точки на карте. Поддержан локальный GeoIP City; база в sandbox пока не установлена из-за ограничения сети.

## Проверки

После импорта вашей выгрузки:

```sh
python -m pip install httpx==0.28.1
python -m unittest discover -s tests -v
```

Есть проверки парсинга, запрета SQL-выражений, атомарного/повторного импорта,
веса, валют, идентификации покупателей, сумм и недель по реальной базе, авторизации,
сохранения настроек и отмены объединения. Проверка заказа №4923 относится к приложенной
выгрузке. `tests/browser_check.py` — браузерная проверка для среды разработки с
Playwright и Chromium. Она запускает отдельный сервер с временной копией данных.

## Удержание: версия 2

В календаре появились минимум/максимум заказов, выбор «за всю историю / за год»,
пресеты 1+, 2+, 5+, 10+ и ровно одна покупка. Есть фильтр сегмента, приоритет контакта
и исключение отложенных/отказавшихся покупателей. CSV учитывает выбранные фильтры;
контакты включаются только при выключенной маскировке имён.

Новые экраны:

- **Очередь контактов:** приоритет 0–100, пороги 2+/5+/10+, причины контакта, CSV.
  В карточке можно отметить контакт, ответ, отказ, запрет контактов или следующую дату.
  При отметке «Связались» без даты используется текущая дата магазина. Заметки приватны.
  Отказы, запреты, будущая дата и пауза после контакта исключают из очереди.
- **Удержание и когорты:** конверсия во вторую покупку за 30/60/90 дней с полным
  окном наблюдения, медиана интервала до второй покупки, первые/повторные заказы по
  неделям, доля суммы повторных заказов и месячные когорты M0–M12.
- **Сегменты и RFM:** восемь правил жизненного цикла, матрица давности/частоты,
  распределение по числу заказов и давности. Каждый сегмент открывает календарь.
- **Повторные продажи:** ожидаемое пополнение конкретной фасовки, дополнения к
  купленным товарам, частые товарные пары, первые товары и возврат за 60 дней, ABC.
- **Сезонность:** часы/дни недели, месяцы, месячная матрица двадцати ведущих товаров.
- **GA4 и каналы:** загрузка CSV, действия на сайте, каналы, сравнение по дням,
  сверка transaction_id с order_id и расхождения сумм.

Когорты основаны на первой наблюдаемой покупке в доступной выгрузке. M0 всегда 100%.
Будущие месяцы не считаются нулевым удержанием; текущий месяц отмечен как неполный.
Метрики не доказывают эффект рекламы или контакта. Сумма покупок не равна прибыли.
RFM: R = 5/4/3/2/1 при давности до 30/60/90/180/больше дней; F = 1/2/3/4/5 при
1/2/3–4/5–9/10+ заказах; M — квинтили суммы покупок доступной базы.
Приоритет — правило на основе частоты, суммы и задержки, не вероятность оттока.
Товарные пары требуют минимум трёх общих заказов; корзины с более чем 100 разными
товарами исключаются из этой выборки, счётчик исключений доступен в данных отчёта.
Lift и доли рассчитаны по уникальным заказам, а не количеству строк или упаковок.

## География по IP

В исходной выгрузке `oc_order.ip` заполнен у всех 4 917 заказов, в том числе у
1 149 заказов без области. Публичный корректный IP не гарантирует, что это именно
IP устройства покупателя: возможны прокси, VPN, мобильная сеть или корпоративный NAT.
`forwarded_ip` сохранён магазином, но автоматически не используется: цепочку заголовков
можно доверять только при известной конфигурации reverse proxy.

Поддерживаются режимы «адрес», «IP» и «адрес + IP при отсутствии области».
Геолокация IP — приблизительное место сети, не подтверждённый адрес доставки.
Страна адреса и область IP из другой страны не склеиваются в одну запись.
Для старых заказов современная геобаза может ошибаться из-за перераспределения адресов.

IP покупателей не отправляются на внешние API. Подключите локальную City MMDB:

```sh
python download_geoip.py --month 2026-10
# Или установите уже скачанный файл:
python import_geoip.py /путь/к/dbip-city-lite-2026-10.mmdb.gz
```

Загрузка идёт только с официального `download.db-ip.com` по HTTPS с проверкой TLS;
проверяются gzip и формат City MMDB, установка атомарная. Сохраняется контрольная сумма.
После установки перезапустите сервер и пересоберите демо. Поддерживается также
GeoLite2 City, полученная законным способом от MaxMind.

В sandbox загрузка DB-IP сейчас блокируется сетевым прокси (CONNECT 403). Домен
`download.db-ip.com` добавлен в черновик разрешённых направлений; сохранение черновика
не применяет настройки само. Пользователь может применить сетевую настройку через
редактор окружения. До появления настоящей геобазы неизвестные области не выдумываются.
DB-IP Lite: https://db-ip.com/db/download/ip-to-city-lite — CC BY 4.0, требуется
атрибуция DB-IP.com. Тестовая GeoIP2-City-Test.mmdb из официального MaxMind-DB используется
только в тестах; она не устанавливается как рабочая геобаза.

Логи сервера понадобятся только для заказов без пригодного IP в БД. Поиск по одному
времени ненадёжен: нужны время с часовым поясом, запрос оформления заказа и желательно
request/session ID либо order_id. При нескольких кандидатах автоматическое совпадение
недопустимо. Старые журналы могут быть уже удалены ротацией.

## Импорт GA4

Для текущей версии не нужны аккаунт Google, токены или ключи. На экране GA4 можно
скачать шаблоны и загрузить реальные CSV, либо использовать CLI:

```sh
python import_ga4.py daily.csv --kind daily --currency UAH
python import_ga4.py transactions.csv --kind transactions --currency UAH
```

Основные колонки дневного отчёта:
`date,sessionDefaultChannelGroup,sessions,activeUsers,addToCarts,checkouts,ecommercePurchases,purchaseRevenue,adCost,currencyCode`.
Обязательны date, channel/sessionDefaultChannelGroup, sessions. Остальные показатели
могут отсутствовать: это неизвестное значение, а не ноль. Сумма дневных activeUsers
не является уникальными пользователями за период и в KPI не выводится.
Показатели действий нельзя считать строгой последовательной пользовательской воронкой.
ROAS доступен только при известных положительных расходах; это не прибыль.

Колонки транзакций:
`date,transactionId,purchaseRevenue,currencyCode,sessionSourceMedium,sessionCampaignName`.
Обязательны дата, transactionId и purchaseRevenue. Поддержаны даты YYYYMMDD,
YYYY-MM-DD, DD.MM.YYYY, разделители запятая/точка с запятой, начальные комментарии GA4.
Повтор ключа день/канал или transaction_id отклоняется целиком, чтобы не удвоить суммы.
Один импорт заменяет только снимок соответствующего типа; даты и валюта фильтруются.
Нужны одинаковые периоды отчётов, валюта и согласованные часовые пояса.

Для сопоставления покупок GA4 должен отправлять `transaction_id`, соответствующий
номеру заказа. Нативного GA4 client_id/user_id в этой SQL-выгрузке нет, поэтому
связать произвольные сессии с покупателями без дополнительной настройки нельзя.
GA4 не предоставляет сырые IP пользователей в отчётах. Подключение Data API через
service account с доступом Viewer можно добавить после проверки настройки ecommerce.
Это необязательно для первых отчётов: достаточно CSV.
