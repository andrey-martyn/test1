Изменения существующего ocStore 3.0.2.0 / UniShop2. Цель — **только
https://test.lavka-speciy.com/** и БД `lavkasp_test`.
Кабинет аналитики, новое приложение, Docker и смена PHP не входят в задачу.

`store/` сохраняет относительные пути магазина. Это выбранные исходники из
предоставленного `111.zip`, а не полная установленная копия OpenCart.
**Не копировать весь репозиторий поверх сайта.** Установка использует только
шесть файлов из [manifest](docs/release-manifest.json).

Подготовленная ветка: `codex/mobile-category`.
Исходная версия: коммит `883aa91`; хеши — [source-baseline.json](docs/source-baseline.json).
Изменения и передача Игорю — [HANDOVER.md](docs/HANDOVER.md).
Отдельный ZIP содержит установочный комплект; тесты и неизменённые опорные
исходники доступны в Git-репозитории.

## Первый запуск на хостинге — только аудит

Если SSH-доступ хостинга к приватному GitHub уже настроен, выполнить в терминале:

```bash
cd /home/lavkasp
git clone --branch codex/mobile-category --single-branch git@github.com:andrey-martyn/test1.git lavka-frontend-work
cd /home/lavkasp/lavka-frontend-work
python3 ops/test_store.py --audit
```

Если папка клона уже существует, не удалять и не перезаписывать её вслепую:
сначала проверить `git status`, затем обновить нужную ветку обычным Git-процессом.
Ошибка GitHub `Permission denied (publickey)` означает, что для хостинга ещё
не настроен доступ к репозиторию. Пароль магазина для GitHub не нужен;
приватные ключи и токены в чат не отправлять.

Аудит не изменяет магазин или БД. Он читает `config.php` и `admin/config.php`
статическим парсером, проверяет пути/симлинки и через PHP CLI выполняет только
SELECT для проверки фактической БД, темы и модификаций. Конфиги магазина не
исполняются. Пароли не печатаются и не сохраняются. Требуются Python 3 и PHP CLI
с mysqli на хостинге; версию PHP менять не нужно.

**Сначала прислать отчёт аудита для разбора. Не запускать `--apply` до проверки
изоляции, активных модификаций и старых правок.** `ok: true` относится только к
проверкам, перечисленным в отчёте; PHP веб-сервера и внешние интеграции этим
запуском не проверяются. Локальные тесты не заменяют проверку на test-сайте.

## Последующая установка после разбора аудита

```bash
python3 ops/test_store.py --check
python3 ops/test_store.py --apply
```

Установщик жёстко ограничен `/home/lavkasp/lavka-speciy.com/test/`, проверяет
исходные/итоговые SHA-256 и сохраняет оригиналы в
`/home/lavkasp/lavka-speciy.com/test_frontend_backups/`. При несовпадении файлов
нужно ручное слияние; обхода проверки `--force` нет. Он не запускает
модификаторы, не удаляет кэш и не меняет БД. Изменения на самом сервере ещё не
проверены. Откат:

```bash
python3 ops/test_store.py --rollback ID_ИЗ_ОТЧЁТА_УСТАНОВКИ
```

## Локальная проверка исходников

В уже подготовленной рабочей среде доступны Python Playwright и Chromium.
Новый магазин/сервис для этих тестов не нужен:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/check_mobile_cards.py
```

Браузерный тест использует штатные JS из архива и искусственный HTML/транспорт.
Он не обращается к магазину или БД. PHP CLI в этой среде отсутствует;
серверный SELECT-пробник необходимо проверить первым аудитом на хостинге.

После изменения исходников обновить manifest и diff:

```bash
python3 ops/build_release.py
```

Новые исходные файлы перед этим должны быть добавлены в Git, чтобы попасть в diff.
