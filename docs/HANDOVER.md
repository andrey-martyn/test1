# Передача Игорю: мобильные карточки, первая исходная версия

Перед сменой путей прочитать [общий контракт](../HOSTING_PATHS.md)
и [план витрины](HOSTING-RELOCATION.md). Этот документ описывает выпуск
витрины; перенос каталогов сам по себе не устанавливает этот выпуск и
не разрешает изменения рабочего магазина. Выпущенные ZIP/хеши сохраняются.

Отдельный пакет для администратора рабочего сайта описан в
[handover/README.md](../handover/README.md). Он содержит читаемую HTML-инструкцию,
пошаговый перенос и откат, список приёмки, ровно шесть конечных файлов,
четыре исходных файла для сравнения и полный diff. Собирается командой
`python3 ops/build_handover.py --output /ABS/OUTPUT`.
Тестовые команды ниже относятся только к истории тестового развёртывания;
в отдельный пакет они не включаются.

## Результат и границы

Два товара в ряд в мобильной категории до 519 px. В списках и каруселях фото
находится над названием; доступные фасовки показаны кружками около 32 px поверх
фото. Слева полная цена выбранной упаковки с подписью веса; справа зелёная
кнопка корзины 36 px. Цена за 100 г и процент экономии исключены.
В последней правке название получает `font-weight:100`; текущий Rubik при этом
выбирает имеющееся начертание 400. URL stylesheet обновлён до `?v=2` для кэша.

Название занимает естественную высоту. Существующие стикеры и избранное
сохраняют штатные данные; фиктивные «Хит», «Эксклюзив» и скидки не назначаются.
Для неизвестных или нескольких групп опций сохранена исходная карточка на
полную ширину. Все варианты остаются доступны. Количество элементов карусели
берётся из штатной настройки темы `items_on_mobile`.

Только исходные файлы, без правок Twig, DB-overrides и сгенерированного кэша.
Настройки и изображения товаров не включены в поставку. Компьютерная версия
сохраняет исходные элементы интерфейса. В каруселях с радиоопциями выключен
бесконечный loop: Owl-копии сбрасывают выбор одинаково названных полей.

## Изменяемые файлы (пути относительно корня магазина)

| Файл | Назначение |
| --- | --- |
| `catalog/controller/extension/module/uni_new_data.php` | Подключение двух новых исходных assets через Document и штатное объединение UniShop2. |
| `catalog/view/theme/unishop2/js/common.js` | Блокировка повторных мобильных покупок на время POST, индикация ответа, защита дубликатов карточек одного товара; отключение Owl-loop у радиоопций. Штатные AJAX и аналитика сохранены. |
| `catalog/view/theme/unishop2/js/live-price.js` | Мгновенный вывод штатного расчёта на мобильных карточках; отмена предыдущей ценовой анимации; локальные переменные и отсутствие повторной регистрации своих обработчиков. |
| `catalog/view/theme/unishop2/js/showmore-ajaxpagination.js` | Подгрузка не сбрасывает фасовки уже существующих карточек и не меняет опции вне сетки. |

Новые файлы:

| Файл | Назначение |
| --- | --- |
| `catalog/view/theme/unishop2/js/lavka-mobile-cards.js` | Небольшой адаптер исходных полей: изоляция радиогрупп без переименования option[…], кружки для native select, подпись веса, инициализация добавленных карточек. Перемещения всего DOM и пересборки каталога на ценовых анимациях нет. |
| `catalog/view/theme/unishop2/stylesheet/lavka-mobile-cards.css` | Мобильная сетка и компоновка через CSS Grid/display:contents, полупрозрачные фасовки и избранное, компактная корзина, загрузка/подтверждение. |

Исходных файлов для удаления **нет**. Изменение БД отдельное: удалить ровно один
проверенный старый CSS-блок из `user_css` в JSON `oc_uni_setting.data`, store_id=0.
Остальные настройки и `user_js` сохраняются. Основание — присланный
`legacy-frontend.zip`; полный CSS до/после, diff, проверки и откат описаны в
[LEGACY-MIGRATION.md](LEGACY-MIGRATION.md). После удаления сохраняются 301 из
1240 байт пользовательского CSS: статьи, слайдер и цвет цены.

Последний присланный аудит подтвердил тему 1.9.0.0, отдельную БД/хранилище и
включённый live-price. Экспорт, миграция и установка на тест выполнены
пользователем; результаты и ID копий — в [TEST-DEPLOYMENT.md](TEST-DEPLOYMENT.md).
Мобильная категория одобрена пользователем и Таней; остальные сценарии ещё
нуждаются в подтверждении. Аудит обнаруживает известные маркеры, но не
гарантирует обнаружение любого стороннего кода. Сброс всех правок не нужен.

## Исходная версия и diff

- Пользовательский архив `111.zip`, полученный 27 октября 2026.
- `111/unishop2/` сопоставлен с `catalog/view/theme/unishop2/` по структуре темы.
- Версия OpenCart из `index.php`: 3.0.2.0. Версия активной темы определяется
  аудитом БД; 1.9.0.0 ранее показана пользователем на скриншоте.
- Базовый коммит: `883aa91`; полные SHA-256 — `docs/source-baseline.json`.
- Изменённые файлы целиком находятся в `store/`; точный diff с контекстом —
  `docs/mobile-category.patch`, с путями относительно корня магазина.
- Manifest содержит только шесть устанавливаемых файлов и хеши до/после.
- Для уже установленной версии `f006edb` есть отдельные
  `docs/title-weight-update.json` и `docs/title-weight-update.patch`: два файла,
  CSS названия 500 → 100 и подключение CSS ?v=1 → ?v=2. Дополнительных изменений
  БД нет. На production Игорь использует ручное объединение актуального diff.
- Дополнительно записаны хеши точных LF-вариантов четырёх исходных файлов.
  У `uni_new_data.php` этот хеш совпал с серверным. Прочие изменения содержимого
  требуют ручного объединения. Откат сохраняет реальные LF/CRLF байты хостинга.

Если содержимое файлов на хостинге отличается от baseline, требуется ручное слияние.
Особенно проверить OCMOD, затрагивающие `uni_new_data.php`, обработчик покупки
и опции. В архиве есть `vetroff_flex_price_cart.ocmod.xml`: новая CSS-компоновка
учитывает его обёртку `.product-thumb__row`. Наличие XML не доказывает, что
модификация активна в БД или что иных модификаций нет.

## Установка и кэши

1. Клон Git и backup расположить вне публичного каталога. Проверить отчёт
   `python3 ops/test_store.py --audit`: оба конфига, realpath всех DIR_*,
   фактическую `lavkasp_test`, тему, live-price, известные старые вставки и OCMOD.
2. Если `uni_new_data.php` перекрыт сгенерированной копией OCMOD, установщик
   остановится. Сначала определить необходимые модификации и согласовать порядок
   их обновления исключительно в тестовой админке. Generated PHP не править
   вместо исходника и не удалять выборочно без понимания потерянных модификаций.
3. Выполнить `python3 ops/migrate_legacy.py --check`, затем `--apply`: проверка
   всех шести файлов предшествует записи БД, а миграция имеет отдельный backup/ID.
   После этого `python3 ops/test_store.py --check`, затем `--apply` устанавливают
   файлы. Полная цепочка — в README. Весь репозиторий поверх сайта не копировать.
4. Новые имена assets меняют список объединения UniShop2, поэтому ожидаются новые
   merged CSS/JS. В них включаются обновлённые common/live-price. Если объединение
   отключено, проверить обычные ответы этих файлов после жёсткой перезагрузки.
5. Если включён LiteSpeed/page cache, очистить его только для тестового хоста
   штатным тестовым инструментом. Подтвердить, что очистка не распространяется
   на соседние установки. Массовое удаление storage или CSS/JS запрещено.
6. Twig не менялся; общего сброса редактора шаблонов не требуется. Обновление
   OCMOD, очистка page cache и проверка веб-PHP пока не выполнялись на сервере.

## Проверки на test.lavka-speciy.com

- Категории на 320, 390 и 432 px: две колонки, без горизонтальной прокрутки;
  длинные названия, 1/4/6 фасовок, перенос кружков, скидочная цена.
- Пересчёт при выборе каждого веса; совпадение цены и фасовки с корзиной.
- Native radio и select, заблокированные опции, минимальное количество >1,
  товары поштучно/мл, без опций и с несколькими группами опций.
- Новинки/карусели, сортировка, лимит, «Показать ещё» и AJAX-пагинация:
  существующий выбор не сбрасывается, новые карточки работают.
- Медленный ответ: одна покупка на серию кликов, спиннер и подтверждение после
  реального ответа. Сетевая ошибка не вызывает автоматического повторного POST.
- Меню, избранное, переход на товар, корзина и оформление; компьютерная версия.
  Реальные заказы и рабочие платёжные/почтовые/аналитические интеграции не запускать.

Локально проверены 11 браузерных сценариев на штатных JS с искусственным
транспортом, 22 сценария установщика/отката на временной файловой системе
и 10 сценариев самого PHP-пробника с фиктивным mysqli. Последние проверяют
схемы store с ssl и без ssl, неоднозначное сопоставление, ошибки SQL и чтение
JSON из uni_setting.data. Также пройдены 4 проверки SQL, собранного самим
PHP-пробником, на MariaDB в одноразовом bootstrap без сети. Исходный запрос
падает с 1064 возле неэкранированного ssl; исправленные запросы проходят обе
схемы. Подключений к БД хостинга в локальных тестах нет.
Четвёртый сценарий проверяет подготовленный UPDATE миграции и защиту от
конкурирующего изменения на настоящем SQL-движке без сети.
Установка на реальном тесте подтверждена SSH-отчётом; отображение категории
одобрено пользователем и Таней. Сценарии покупки ещё не подтверждены. Реальная
причина ожидания 5–7 секунд не установлена: в присланном live-price.js нет запроса к серверу,
а его анимация задана на 300 мс. Подготовленная версия убирает эту анимацию на
мобильном и повторные покупки, но не обещает устранение неизвестной серверной
задержки. После установки измерить checkout/cart/add и common/cart/info отдельно.

Для безопасного экспорта дополнительно пройдены 12 сценариев: пять с настоящим
PHP и фиктивным mysqli, семь на временной файловой системе/фиктивных ответах.
Проверены однократное декодирование исходных вставок, отсутствие остальных
настроек в результате, права архива, тестовая БД и сохранение остальных
предварительных проверок. Дополнительно пройдены 16 проверок миграции: точное
сохранение остального JSON, выборочные кэши, частичный сбой, повторный запуск,
откат без потери более поздних посторонних настроек и ограничения PHP-моста.
Пройдены все 64 локальные проверки инструментов, включая отдельный manifest
обновления уже установленных файлов и запрет путей вне docs. На хостинге
выполнены аудит, экспорт, миграция и первая установка шести файлов; правка
weight 100 пока подготовлена только в Git.

## Откат и дальнейшая передача

`python3 ops/test_store.py --rollback BACKUP_ID` проверяет, что после установки
файлы не менялись, восстанавливает исходные четыре файла и удаляет два новых.
Права сохраняются. При частичной ошибке установки выполняется восстановление
из уже созданного backup. Кэш тестового хоста при необходимости очистить штатно.

Затем `python3 ops/migrate_legacy.py --rollback MIGRATION_ID` возвращает только
исходное поле CSS и инвалидирует его тестовый файловый кэш. Если CSS с тех пор
менялся, автоматический откат остановится для ручного объединения. Остальные
более поздние настройки/JavaScript не затираются. Кэши регенерирует магазин.

Production самостоятельно не обновляется. После утверждения Игорь вручную
сверяет свои исходники с baseline и переносит diff/полные файлы. Не переносить
`ops/test_store.py` и `ops/migrate_legacy.py` как production-установщики: они привязаны к
тестовым путям и БД. Конфигов, паролей, клиентских данных, DB-дампов, кэша и
подмены адресов сайта в комплекте нет.
