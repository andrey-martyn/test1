# Отдельная миграция старого CSS сетки

## Что меняется

На основании переданного `legacy-frontend.zip` подтверждено:

- Тестовая БД `lavkasp_test`, JSON в `oc_uni_setting.data`, `store_id=0`.
- `user_js` выбирает первую radio-фасовку; сохраняется целиком.
- В `user_css` полезные стили статей/слайдера/цены занимают 301 байт.
  Следом один устаревший блок с комментарием
  `/* Две карточки в категориях по штатной настройке UniShop2 */`
  и селекторами `#content[data-lavka-mobile-grid="2"]`.
- Удаляется только этот конечный блок; из 1240 декодированных байт CSS остаются 301.
  Другие поля, объекты `{}`, числа и исходное форматирование остального JSON
  сохраняются побайтно. Каталог/цены/опции товаров и таблицы заказов не меняются.

Материалы для проверки:

- План и SHA-256: `ops/migrations/legacy-grid.json`.
- Полный исходный CSS: `ops/migrations/legacy-grid-before.css`.
- Полный оставшийся CSS: `ops/migrations/legacy-grid-after.css`.
- Diff декодированного CSS: `docs/legacy-grid.patch`.
- Исполнитель на хостинге: `ops/migrate_legacy.py`.
- PHP-мост SELECT/подготовленного UPDATE: `ops/migrations/user-css.php`.

Эти служебные файлы остаются в Git-клоне вне сайта, в корень магазина их
не копировать. Конфигов подключения, лицензии и копии всей строки настроек
в поставке нет. В `migration.json` сохраняется только CSS. Закрытые копии кэша
могут содержать остальные настройки темы; они остаются на хостинге и не входят
в передачу Игорю или отчёт в чат.

## Проверки и порядок

`--check` повторяет проверку обоих конфигов/изолированных путей и фактической
тестовой БД, источника настроек, всех шести файлов релиза, точных хешей
`user_css`/`user_js` из выгрузки и SHA-256 модели загрузки настроек. Известный
legacy-маркер допускается только этим мигратором для проверенной операции;
остальные ошибки аудита остаются блокирующими. Сценарий ничего не исполняет
из пользовательских вставок и не запускает bootstrap магазина.

`--apply` заново выполняет проверки. Исходный JSON-литерал только поля CSS
сохраняется в `test_frontend_backups/legacy-grid-<ID>/migration.json` вне сайта.
Права каталога 700, файлов 600. Затем UPDATE с параметрами заменяет строку
только при полном BINARY-совпадении с прочитанной: конкурирующее изменение
настроек не затирается. PHP дополнительно запрещает изменение любого другого
JSON-поля. При сбое после записи выполняется восстановление исходного CSS;
если восстановление невозможно, печатается `MIGRATION_RECOVERY_REQUIRED`
с ID резервной копии. Полное содержимое настроек и пароль в терминал не выводятся.

После записи копируются в закрытый backup и удаляются только:

- `test_storage/cache/cache.unishop.settings.0.<числовой суффикс>`;
- `test/catalog/view/theme/unishop2/stylesheet/generated-user-style.0.css`.

Речь только о файловом кэше внутри проверенной тестовой установки. Другие
магазины, `product.unishop`, остальные CSS/JS, модификации, Twig, сессии и внешние
кэши не очищаются. Перед удалением generated CSS сверяется с известным CSS
до/после, с учётом только LF/CRLF; неизвестное содержимое останавливает операцию.
Сгенерированный CSS не редактируется как исходник: его создаст штатный UniShop2
по очищенному полю. Кэш настроек не восстанавливается из старой копии при откате,
чтобы более поздние настройки не подменились устаревшим снимком.

Полная цепочка для теста:

```bash
cd /home/lavkasp/lavka-speciy.com/apps/lavka-frontend &&
git pull --ff-only origin codex/mobile-category &&
python3 ops/migrate_legacy.py --check &&
python3 ops/migrate_legacy.py --apply &&
python3 ops/test_store.py --check &&
python3 ops/test_store.py --apply
```

Сохранить оба `rollback_id`. Если установка файлов остановилась после успешной
миграции, в БД уже сохранено очищенное поле CSS; резервная копия и отдельный
откат остаются доступны. Весь запуск не является одной транзакцией БД/файловой
системы. Внутри операции миграции и внутри установки файлов предусмотрено
восстановление при частичном сбое. Повтор самой миграции распознаёт уже очищенное
поле, но установка файлов остаётся привязанной к исходным хешам.

## Откат

Сначала откатить установку файлов, если она была выполнена, затем CSS:

```bash
python3 ops/test_store.py --rollback ID_ФАЙЛОВ
python3 ops/migrate_legacy.py --rollback legacy-grid-ID_МИГРАЦИИ
```

Откат CSS восстанавливает оригинальное JSON-представление только этого поля,
сохраняя последующие изменения других настроек. Если само поле CSS изменилось
после миграции, требуется ручное слияние. После отката кэш регенерируется.

## Передача Игорю

Оба установочных инструмента намеренно работают только с тестовыми путями/БД;
на рабочий сайт их не адаптировать простым удалением проверок. Игорю передаётся
исходный diff CSS и описание точной операции отдельно от шести исходных файлов
фронтенда. На рабочем магазине сначала сверить актуальное поле CSS и сохранить
его вне публичного каталога; при отличиях объединить вручную, сохранив все
остальные блоки. Тестовые настройки и резервные копии/кэши не переносить.
