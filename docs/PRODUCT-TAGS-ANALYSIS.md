# Метки товаров: результаты разбора

28 октября 2026. Ветка `codex/product-tags`; только test.lavka-speciy.com и
lavkasp_test. Реальный хостинг из этой среды недоступен: установка выполняется
пользователем через SSH после проверки установщиком.

## Что подтвердилось

- Пользователь подтвердил: разница между категорией и страницей товара была
  **кэшем страницы категории**. После очистки все заданные стикеры появились.
  Ограничения «показывать только один» в исходном коде нет.
- Общий `uni_stickers.twig` перебирает весь `product.stickers` и используется
  категориями, страницей товара и модулями темы.
- Модель `catalog/model/extension/module/uni_new_data.php` получена в `222.zip`.
  Она формирует штатные стикеры. Одноимённый контроллер выполняет другую работу.
- «Новинка» считается от **date_available**, к которой прибавляется срок
  `sticker_new_date`. Редактирование товара не должно запускать этот срок заново.
- Штатный «Лидер продаж» определяется количеством проданных единиц и кэшем
  `unishop.sticker.bestseller.<store_id>`. Это отдельный источник от текста MPN.
- Штатная сортировка стикеров идёт по убыванию байтовой длины текста, поэтому
  порядок полей не совпадает с порядком в админке.
- Цвета UPC/EAN/JAN/ISBN/MPN имеют правильные имена полей в настройках темы и
  генераторе CSS. Общая `opacity:.8` меняет воспринимаемые цвета. Но прозрачные
  UPC/EAN на старом скриншоте одной прозрачностью не объясняются: действующие
  generated/merged CSS в архив не вошли. Точный старый каскад не установлен.

## Полученные исходники

Из `222.zip` выбраны только нужные исходники админки и каталожной модели.
`admin/config.php` исключён и не читался. Полный архив в Git не публикуется.
Исходная версия выбранных файлов — коммит `647cb88`, хеши и происхождение:
[product-tags-source.json](product-tags-source.json).

Общий `uni_stickers.twig` отсутствовал в `222.zip`: использована версия из
ранее полученного `111.zip`. Установщик принимает её точный хеш или записанный
вариант окончания строк. Если на хостинге другая версия, он остановится.
Код LSCache из архива изучен для вызова штатного адресного сброса; сам модуль
LSCache в обновление не входит. Защищённый модуль настройки UniShop2
не выполняется и не редактируется.

## Принятое устройство

Пять маркетинговых типов: автоматические «Новинка» и «Топ продаж», три
ручных признака «Свежий помол», «Наша марка», «Эксклюзив». Их настройки
отделены от SKU/UPC/EAN/JAN/ISBN/MPN, цены, остатка и SEO-тегов OpenCart.

После первого выпуска пользователь уточнил правило Топа: считать проданные
упаковки за всё время, включая несколько упаковок в одном заказе. Не вводить
топ-10 или отдельный период. Принят начальный порог 11 («более 10»), настраиваемый
в оформлении меток. Считаются SUM(order_product.quantity) только по завершённым
заказам текущего магазина. Пустой список завершённых статусов даёт пустой
результат и предупреждение, без расширения на любые ненулевые статусы.
Агрегат кэшируется на 30 минут, загружается один раз на запрос, без SQL для
каждой карточки. Штатный устаревший расчёт Лидера больше не вызывается.

Один сервис формирует метки для всех витрин. Названия RU/UA, включение, фон,
цвет текста и порядок задаются на отдельной странице. Новые настройки не
записываются в закрытую структуру настройки темы. Для старых field-as-sticker
берутся актуальные разрешённые ключи цветов штатной темы и проверяются как HEX.
Цвета передаются непосредственно в разметку, общая прозрачность снята.

Прежние ручные назначения Хита и маркетинговый MPN сохраняются в БД,
но больше не назначают автоматический Топ. Остальные кодовые поля остаются
обычными стикерами, если их показ включён в теме. Числа 1111–4444 не удаляются
и не превращаются в маркетинговые признаки.

В списке после названия: три ручные галочки, автоматический Топ с подсказкой
о количестве продаж/пороге и статус «Новинки». Сверху списка добавлена
заметная кнопка «Метки товаров» для изменения названий RU/UA, цветов и порога.
Тот же блок есть в форме товара. Ручное сохранение частичное, с правами,
токеном и ревизией. Попытка вручную назначить Топ отклоняется до SQL.
Мобильная форма меток возвращена к плоскому ярлыку со скосом справа;
версия URL CSS повышена. Ни одного назначенного стикера не скрываем.

Для устаревшего HTML-кэша предусмотрен пакетный POST-запрос за свежими
метками видимых товаров. Он не возвращает цены, остатки, настройки или скрытые
товары и не пишет в БД товаров. Переключение веса таких запросов не создаёт.
Сохранение дополнительно вызывает штатный путь сброса LSCache для товаров
и категорий. Первая установка требует очистки HTML-кэша **тестового** хоста,
чтобы в старой странице появился новый скрипт.

## Проверено и что осталось проверить

Автоматически проверены композиция всех меток, языки/цвета, сроки, наследование,
частичные обновления, конфликты и транзакции, порог 10/11, сумма упаковок
одного заказа и расширение прежней собственной схемы без потери оформления. SQL выполнен в отдельном
локальном InnoDB-процессе без сети. Браузерные проверки с имитацией HTTP:
320/390/432/1280 px, пять меток и шесть фасовок, отсутствие наложений,
повторные карточки, обновление после кэша и безопасный вывод текста.

Это проверки исходников и изолированных сценариев. Работа действующих
OCMOD-копий, веб-версии PHP, LiteSpeed и внешних дополнений подтверждается
после установки на тест по [инструкции](PRODUCT-TAGS-INSTALL.md). Прежняя
серверная задержка корзины этим изменением не диагностировалась.
