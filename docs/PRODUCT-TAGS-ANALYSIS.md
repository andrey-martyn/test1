# Теги товаров: предварительный разбор и нужные исходники

Новая задача от 28 октября 2026. Работа только с тестовым магазином/БД.
Ветка `codex/product-tags` отделяет задачу от уже переданного пакета карточек.
На этом этапе выполнен разбор, исходники сайта и БД не изменяются.

## Что видно на скриншотах

- На странице товара показаны MPN «Популярно» и значения EAN/ISBN/JAN/UPC.
  В категории того же товара остаётся только «Популярно».
- После удаления MPN со страницы товара тег уходит, в категории остаётся.
- Для UPC/EAN указаны цветные фоны, но на странице они выглядят прозрачными;
  JAN/ISBN получают синий/жёлтый фон. Это не объясняется одним только opacity.
- Редактирование дополнительных полей на скриншоте содержит предупреждение:
  подписи работают, только когда поле не используется как стикер. Эти подписи
  нельзя считать отдельной системой тегов или переключателем их показа.
- Красная зона находится в списке товаров: требуется новая колонка рядом с
  названием, а не только дополнительные поля внутри формы одного товара.

## Что уже подтверждено исходниками

1. Категория и страница товара включают общий
   `catalog/view/theme/unishop2/template/extension/module/uni_stickers.twig`.
   В нём цикл по всем `product.stickers`; ограничения «первый тег» нет.
2. Страница товара получает стикеры через модель
   `extension/module/uni_new_data`, метод `getNewData` с `product_page=true`.
   Самой модели в архиве 111.zip нет. В репозитории есть одноимённый КОНТРОЛЛЕР,
   он не заменяет отсутствующую модель.
3. В исходных category.php/model catalog/product.php из архива нет UniShop-хуков:
   действующие изменения, вероятно, приходят через OCMOD. Для точного сравнения
   нужны исходные модификации или соответствующие действующие compiled-копии.
4. `uni_tool.php` формирует CSS для всех sku/upc/ean/jan/isbn/mpn. Генерация
   `generated.<store_id>.css` прекращается, если файл уже существует; merged CSS
   также повторно используется по имени из списка URL. Нужно проверить сброс
   этих файлов в админском обработчике сохранения настроек.
5. Базовый `.sticker__item` имеет opacity .8: заданные HEX визуально смешиваются
   с фоном фото. Отсутствие фона отдельных тегов требует дополнительной проверки
   классов, сохранённых ключей цвета и реально загруженного CSS.
6. Наш `lavka-mobile-cards.css` меняет геометрию стикеров, но не назначает им
   фон/цвет и не ограничивает количество. Однако его адаптивную компоновку
   нужно проверить с пятью тегами и несколькими строками кружков фасовок.

Точная причина ещё не установлена. Для «Популярно» надо отличить MPN от
штатного bestseller: одинаковая надпись может иметь разные источники.
Также проверяются кэши данных товара, списка, HTML и скомпилированных стилей.
Нельзя объяснять весь случай только браузерным кэшем без проверки модели.

## Предлагаемая система

| Тип | Источник | Управление в списке товаров |
| --- | --- | --- |
| Новинка | Существующее автоматическое правило/период UniShop2 | Автостатус и окончание периода; не притворяться ручным чекбоксом |
| Хит продаж | Ручной маркетинговый признак | Чекбокс |
| Свежий помол | Ручной признак | Чекбокс |
| Наша марка | Ручной признак | Чекбокс |
| Эксклюзив | Ручной признак | Чекбокс |

- Единый набор типов/названий/цветов/порядка; общий сборщик тегов для категории,
  страницы товара и модулей. Не делать отдельный расчёт для каждого шаблона.
- Показ всех активных назначенных тегов без скрытого ограничения количества.
  Фиксированный порядок, отсутствие дубля «Хит/Популярно» из разных источников.
- Сохранить штатное правило автоматической Новинки после просмотра модели;
  изменение других полей не должно продлевать её срок. Кэш учитывает истечение.
- Четыре новых/ручных признака хранить отдельно от SKU/UPC/EAN/JAN/ISBN/MPN:
  это идентификаторы товара, используемые интеграциями и микроразметкой.
  Точную схему выбрать после просмотра существующего кода, оформить отдельной
  тестовой миграцией с backup/откатом. «Популярно» можно переносить только по
  подтверждённому правилу; тестовые 1111/2222/3333/4444 не превращать в признаки.
- Включённые старые field-as-sticker остаются совместимыми и выводятся единообразно,
  пока проводится переход. Кодовые поля не стирать и не переименовывать вслепую.
- Настройка типа содержит название RU/UA, включение, цвет фона, цвет текста,
  порядок. Точные цвета без общей opacity; предпросмотр и проверка HEX.
  Глобальное отключение скрывает тип на всех витринах, сохраняя назначения.
- В админском списке колонка «Метки»: четыре чекбокса 2×2 и автостатус Новинки.
  Изменение сохраняется отдельно через AJAX с индикацией успеха/ошибки.
  Запрос меняет только выбранный признак, не пересохраняет весь товар.
  Проверить права modify catalog/product, токен, product_id и допустимый тип;
  конкурентные изменения не должны затираться. Страница/фильтры сохраняются.
- Изменения из списка и из формы товара используют одну логику записи/кэша.
  Не допускать SQL-запроса на каждый тег каждой карточки: загрузка пакетная.
- На телефоне теги не перекрывают избранное/фасовки; проверить 320/390/432 px,
  пять тегов и шесть весов. При нехватке места адаптировать компоновку, а не
  скрывать часть назначенных тегов.

## Какие файлы подготовить

Корень источников FTP: `/lavka-speciy.com/test/`. Рабочий сайт не выгружать.
Размещать свежие исходники в `incoming/product-tags/source/`, сохраняя пути
относительно корня магазина. Отсутствующие пути просто отметить в README.

### Обязательные недостающие модели и админка

```text
catalog/model/extension/module/uni_new_data.php
catalog/model/extension/module/uni_settings.php

admin/controller/catalog/product.php
admin/model/catalog/product.php
admin/view/template/catalog/product_list.twig
admin/view/template/catalog/product_form.twig
admin/language/*/catalog/product.php

admin/controller/extension/module/uni_settings.php
admin/model/extension/module/uni_settings.php                 (если существует)
admin/view/template/extension/module/uni_settings.twig        (если существует)
admin/view/template/extension/module/uni_settings/             (вложенные Twig, если есть)
admin/language/*/extension/module/uni_settings.php
```

`*` здесь означает фактические установленные RU/UA языковые папки. Для
настроек нужны основной Twig и подключаемые им вкладки стикеров/допполей:
если имена отличаются, передать файлы/папку с префиксом uni_settings.

### Диагностика действующих модификаций и цветов

В отдельную папку `incoming/product-tags/diagnostics/`, не поверх исходников:

- XML OCMOD UniShop2 и других модификаций, затрагивающих список/форму товаров,
  стикеры или catalog/model/catalog/product.php, если готовый XML доступен.
- Если XML пока нет, из `test_storage/modification/` передать только существующие
  копии перечисленных выше product/category, admin product и Twig-файлов.
  Сохранить их относительные пути под `diagnostics/modification/`.
  Это чтение для сравнения, не будущие исходники для редактирования.
- Текущие `generated.0.css`, `generated-user-style.0.css` из stylesheet —
  только для диагностики. Их не будем редактировать как исходник.
- Только те `merged.*.min.css`, которые реально подключены на проблемных
  категории и странице товара. Имена видны в DevTools → Styles/Network;
  весь каталог кэша не требуется.

Конфиги, ключи, лицензия, дамп БД, cache/logs/session и папка storage целиком
не нужны. Содержимое uni_setting.data целиком не выгружать: там есть другие
настройки. Если понадобится сверка значений, подготовим SELECT-отчёт только
по разрешённым ключам стикеров, а не по всей строке.
