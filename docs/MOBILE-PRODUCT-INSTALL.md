  пять в ряд от 320 px, белый фон 40%, выбранный зелёный 82%, прежние галерея,

- Основной ряд покупки под метаданными сохраняет цену, подпись «за …», −/+ и
  кнопку без значка корзины. Под ценой одна подпись «за 50 г / 2.4 €» с более
  светлым евро. Длинное описание после покупки.
- Защита от повторных нажатий, нативный AJAX/аналитика, проверка опций и пересчёт
  цены сохранены. При ошибке нет автоматического повторного заказа.

Поддерживаются граммы, килограммы, объём и штуки в одном обычном radio/select.
Первый доступный вариант выбирается только на мобильном экране и только для
одной распознанной группы фасовок, если ещё ничего не выбрано. Уже выбранный
вариант сохраняется. Неизвестные/несколько групп, опции с изображениями,
дополнительные обязательные поля и периодичность остаются штатными.

Цена в гривнах считается существующим `live-price.js`, в корзину отправляет
существующий обработчик `product.twig`. Видимая сумма в евро — один пересчёт
уже вычисленного нативного `old-price` / `old-special` по тому же `data-eurcurr`
с округлением до одного знака. Поэтому учитываются выбранная фасовка, акция
и скидка за количество. Старый отдельный `.eur-price` сохраняется скрытым
внутри `product-block` для совместимости; на десктопе его оформление возвращается. Нижняя кнопка нажимает оригинальную кнопку, отдельного
POST нет. Цены в гривнах, скидки и остатки не вычисляются новым независимым алгоритмом.
В мобильной странице товара без опубликованных отзывов показан переход
«Написати відгук». В одобренных карточках категории нулевой блок остаётся скрытым.
«Доставка й оплата» открывает нижнюю модальную панель, сохраняя товар, выбранную
фасовку, количество и позицию прокрутки. Используется нативный `<dialog>`:
закрытие крестиком, касанием фона или Escape, фокус возвращается к кнопке.
На время открытия нижняя покупка скрывается, фон не прокручивается.
Блокировка действует на корневой элемент страницы: overflow на body
с фиксированной навигацией сбрасывал прокрутку; этот вариант устранён.
После закрытия восстанавливаются прежняя позиция и видимость нижней планки.

Воспроизведена причина пропавших отступов v6: регулярные выражения штатного
`uni_tool.php` удаляют пробелы вокруг `+` в `calc()`. Браузер отбрасывает целиком
правило padding: в локальном сравнении цена сдвигалась с 16 px к самому краю.
В v7 внутренний ряд имеет обычные поля, безопасная область задана отдельно,
сложения в CSS нет. Нижний отступ страницы равен измеренной высоте панели + 8 px,
включая безопасную область. Свойство удаляется при возврате на десктоп.
Сборщик темы не меняется; регрессионный тест исполняет его исходные восемь замен.

Условия читаются при первом открытии GET-запросом к существующей информационной
странице из ссылок header/footer текущего магазина. Поддержаны объединённая
страница и отдельные ссылки доставки/оплаты RU/UA/EN. Ссылки на основной домен
в меню теста читаются по тому же пути на тестовом домене; другие внешние адреса
автоматически не загружаются. Шаблоны, настройки и текст исходной страницы
доставки не меняются.

Попап использует отдельный Shadow DOM с собственными стилями внутри JS.
Внешние CSS-правила темы не могут обнулить внутренние поля, изменить размеры
абзацев или списков. Изолированы заголовок, закрытие и прокручиваемая область.
Тест добавляет конфликтующие правила с `!important` и проверяет прежние отступы
и 14 px текста. На внешнем dialog есть `data-lavka-product-version="7"`.

После очистки разметки редактора содержимое группируется по существующим
заголовкам. Первыми показаны открытые «Доставка» и «Оплата», контакты и оформление
заказа — ниже, раскрываются нажатием. Порядок текста внутри разделов сохраняется;
новые сроки, тарифы или обещания не создаются. Если заголовки не распознаны,
чистый текст остаётся доступен целиком. Пустые абзацы/nbsp/повторные br удалены,
списки и таблицы имеют внутренние поля, жирное выделение умеренное. Копируются
только безопасные текстовые элементы и ссылки; скрипты, формы и встроенные
обработчики источника не исполняются. Условия повторно используются на этой
странице; при ошибке есть повтор загрузки без перехода с товара.

Шаблон Twig, настройки редактора шаблонов, PHP-версия, серверная логика корзины,
аналитика и БД не изменяются. `uni_new_data.php` и файлы категории не меняются:
новые CSS/JS подключаются только контроллером страницы товара.

## Установка на тест

Сначала сохранить незакоммиченные локальные изменения Git, если они есть.
Не использовать принудительный reset/checkout. Все команды выполняются
в существующем репозитории вне публичной папки магазина.

```bash
cd /home/lavkasp/lavka-frontend-work &&
git remote set-branches --add origin codex/mobile-product &&
git fetch origin &&
git checkout codex/mobile-product &&
git pull --ff-only origin codex/mobile-product &&
python3 ops/product_page.py --check &&
python3 ops/product_page.py --apply
```

Для следующих обновлений этой ветки достаточно `git pull --ff-only origin
codex/mobile-product`, затем те же `--check` и `--apply`.
Выпуск v7 принимает чистый исходник категории и точные версии ранее
установленных v1 (4c9719c), v2 (f30a4fc), v3 (75c5e5f), v4 (485e1fc), v5 (0d04893)
и v6 (74a7233). Обновление сохраняет прежние
CSS/JS/контроллер в резервной копии; откат возвращает именно установленную версию.
Посторонние изменения файлов по-прежнему останавливают установку.
Команды `ops/product_tags.py` и старого мобильного выпуска эту доработку
не устанавливают. Ввод паролей в переписку не требуется.

Проверка только читает БД: подтверждает обе конфигурации, фактическую БД,
store_id=0, пути и ссылки, тему, включённый штатный пересчёт цены. Отдельно
проверяются исходный `product.twig` и его эффективное переопределение в
редакторе шаблонов, если оно есть. Учитываются только текущий store_id,
активная тема и точный маршрут `product/product`, как в штатном загрузчике. Источник — предоставленные 111.zip / 222.zip;
хеши в [product-page-source.json](product-page-source.json).

При `SOURCE_HASH_MISMATCH`, `PRODUCT_SOURCE_MISMATCH` или
`PRODUCT_TEMPLATE_OVERRIDES_UNVERIFIED` установка останавливается до записи.
Нужно сравнить названный **тестовый** исходник/переопределение; не сбрасывать
чужие изменения и не обходить проверку. Новых таблиц или миграций нет.

### Если проверка остановилась на переопределении товара

Первая версия проверяла все записи с похожим маршрутом независимо от темы.
Уточнённая проверка повторяет выбор штатных `catalog/controller/event/theme.php`
и `catalog/model/design/theme.php`: store_id=0, активная тема, точный маршрут.
Записи другой темы, магазина или другого маршрута не считаются активными.

При одной активной записи её код декодируется один раз через
`html_entity_decode(..., ENT_QUOTES, UTF-8)`, как на витрине, и сравнивается
по SHA-256 с изученным исходником. Приняты записанные варианты LF/CRLF.
Совпадающее переопределение допускается без записи в БД. Отличающееся,
слишком большое, неоднозначное или не прочитанное — останавливает установку.
Само наличие записи не повод её удалять; автоматического сброса нет.

Короткая диагностика без записи в магазин или БД:

```bash
cd /home/lavkasp/lavka-frontend-work &&
git pull --ff-only origin codex/mobile-product &&
python3 ops/product_page.py --diagnose
```

`template_check` показывает `count`, область `scope`, ID/размер/хеши записей
и состояние: `no_active_override`, `active_override_matches_reviewed_source`,
`active_override_differs` или ошибку чтения. Текст шаблона и пароли в отчёт
не попадают. При SQL-ошибке выводятся только стадия и номер ошибки.
`source_files` отдельно сравнивает предоставленный файл с диском теста.

Если активный код отличается, экспортировать **один** эффективный шаблон
для разбора, сохранив БД и текущую витрину:

```bash
python3 ops/product_page.py --export-template
```

В `export.exported` будет путь к `active-product.twig` внутри
`test_frontend_backups/product-template-review-<дата>/`, вне публичной папки
и Git. Файл создаётся с правами 0600, каталог 0700. При изменении кода между
проверкой и экспортом чтение остановится. Для разбора можно передать этот
один файл из FTP; конфиги и дамп БД не нужны. После сверки источника обновляется
перечень изученных хешей, а не запись редактора шаблонов.

`--apply` сохраняет точные копии вне публичной папки в
`/home/lavkasp/lavka-speciy.com/test_frontend_backups/<rollback_id>/`.
Сохранить выданный `rollback_id`. Повторный запуск безопасен: текущие файлы
пропускаются. Пароли, содержимое конфигов и клиентские данные не выводятся.

После установки:

1. Если в `ocmod_refresh_required_for` указан `catalog/controller/product/product.php`,
   в **тестовой** админке обновить «Расширения → Модификаторы». Иначе выполняться
   продолжит старая сгенерированная копия контроллера, без новых подключений.
   Генерированные файлы вручную не редактировать.
2. Очистить HTML-кэш только `test.lavka-speciy.com`, при необходимости — штатный
   merged-кэш темы тестовой установки. Не сбрасывать все сайты аккаунта.
3. Открыть товар и выполнить Ctrl+Shift+R. Шаблон не менялся, отдельное
   редактирование/сохранение Twig не требуется.
4. В Network проверить успешную загрузку `lavka-mobile-product.css?v=7` и
   `lavka-mobile-product.js?v=7`. В консоли не должно быть новых JS-ошибок.

- 320/390/432 px: порядок блоков, длинное название, отсутствие горизонтальной
  прокрутки, читаемость, метки, избранное и увеличение фото.

- Навигация закреплена ниже плавающего меню; выбранные характеристики/отзывы
  видны под ней. Число отзывов обновляется без появления слова рядом с иконкой.
- Доставка открывается поверх товара, текст совпадает с информационной страницей.
  Крестик/Escape/фон закрывают панель; фасовка, количество и прокрутка сохраняются.
  Доставка/оплата раскрыты первыми; контакты/заказ раскрываются по запросу.
  Нет пустых экранов между блоками, списки с отступом, стили темы не вмешиваются.
- Крошки на сером фоне. Вкладки 8 px; при закреплении верхние углы прямые.
  Нижняя панель 16 px сверху. Контролы 8 px, фото 16 px, круглые фасовки сохранены.
- Верхние две планки одинаковой ширины, без щели; навигация не исчезает в футере.
  Нижняя панель белая, высотой 72 px плюс безопасная область, края 16 px.
