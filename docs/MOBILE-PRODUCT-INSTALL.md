# Мобильная страница товара — тестовый выпуск

29 октября 2026. Ветка `codex/mobile-product`, от одобренной категории e28c21a.
Только `test.lavka-speciy.com`, БД `lavkasp_test`, отдельное `test_storage`.
Прямого подключения к хостингу из этой среды нет: установку выполняет владелец
через SSH. Десктоп начинается с 768 px и сохраняет прежнюю разметку и оформление.

## Что изменено

- Название, наличие и существующий рейтинг перед фото. Фотография со
  скруглением и прежними метками; исходные миниатюры, увеличение и избранное.
- Покупка перед длинным описанием: крупные фасовки, цена выбранного варианта,
  подпись «за …», количество с кнопками −/+, зелёная кнопка покупки.
- После прокрутки блока покупки — нижняя панель с текущей суммой и той же
  покупкой. При возврате к основному блоку, работе с текстовым полем или
  открытом модальном окне панель скрывается. Учитывается нижняя безопасная
  область экрана; при открытой панели добавлен отступ перед концом страницы.
- Во время запроса покупки показан статус, повторные нажатия блокируются.
  При ошибке сети — предложение проверить корзину, без автоматического повтора.
- Галерея и количество доступны с клавиатуры, основные кнопки не меньше
  44 px по высоте. Радио/селекты, названия полей и обработчики темы сохраняются.

Поддерживаются граммы, килограммы, объём и штуки в одном обычном radio/select.
Первый доступный вариант выбирается только на мобильном экране и только для
одной распознанной группы фасовок, если ещё ничего не выбрано. Уже выбранный
вариант сохраняется. Неизвестные/несколько групп, опции с изображениями,
дополнительные обязательные поля и периодичность остаются штатными.

Цена считается существующим `live-price.js`, в корзину отправляет существующий
обработчик `product.twig`. Нижняя кнопка нажимает оригинальную кнопку, отдельного
POST нет. Цены, скидки и остатки не вычисляются новым независимым алгоритмом.
Отзывы без опубликованных записей, как и в категории, не показываются.
Доставка и оплата используют существующие данные/блоки магазина; новых
обещаний о сроках, бесплатной доставке или скидках нет.

Шаблон Twig, настройки редактора шаблонов, PHP-версия, серверная логика корзины,
аналитика и БД не изменяются. `uni_new_data.php` и файлы категории не меняются:
новые CSS/JS подключаются только контроллером страницы товара.

## Установка на тест

Сначала сохранить незакоммиченные локальные изменения Git, если они есть.
Не использовать принудительный reset/checkout. Все команды выполняются
в существующем репозитории вне публичной папки магазина.

```bash
cd /home/lavkasp/lavka-frontend-work &&
git remote set-branches --add origin codex/mobile-product &&
git fetch origin &&
git checkout codex/mobile-product &&
git pull --ff-only origin codex/mobile-product &&
python3 ops/product_page.py --check &&
python3 ops/product_page.py --apply
```

Для следующих обновлений этой ветки достаточно `git pull --ff-only origin
codex/mobile-product`, затем те же `--check` и `--apply`.
Команды `ops/product_tags.py` и старого мобильного выпуска эту доработку
не устанавливают. Ввод паролей в переписку не требуется.

Проверка только читает БД: подтверждает обе конфигурации, фактическую БД,
store_id=0, пути и ссылки, тему, включённый штатный пересчёт цены. Отдельно
проверяются исходный `product.twig` и его эффективное переопределение в
редакторе шаблонов, если оно есть. Учитываются только текущий store_id,
активная тема и точный маршрут `product/product`, как в штатном загрузчике. Источник — предоставленные 111.zip / 222.zip;
хеши в [product-page-source.json](product-page-source.json).

При `SOURCE_HASH_MISMATCH`, `PRODUCT_SOURCE_MISMATCH` или
`PRODUCT_TEMPLATE_OVERRIDES_UNVERIFIED` установка останавливается до записи.
Нужно сравнить названный **тестовый** исходник/переопределение; не сбрасывать
чужие изменения и не обходить проверку. Новых таблиц или миграций нет.

### Если проверка остановилась на переопределении товара

Первая версия проверяла все записи с похожим маршрутом независимо от темы.
Уточнённая проверка повторяет выбор штатных `catalog/controller/event/theme.php`
и `catalog/model/design/theme.php`: store_id=0, активная тема, точный маршрут.
Записи другой темы, магазина или другого маршрута не считаются активными.

При одной активной записи её код декодируется один раз через
`html_entity_decode(..., ENT_QUOTES, UTF-8)`, как на витрине, и сравнивается
по SHA-256 с изученным исходником. Приняты записанные варианты LF/CRLF.
Совпадающее переопределение допускается без записи в БД. Отличающееся,
слишком большое, неоднозначное или не прочитанное — останавливает установку.
Само наличие записи не повод её удалять; автоматического сброса нет.

Короткая диагностика без записи в магазин или БД:

```bash
cd /home/lavkasp/lavka-frontend-work &&
git pull --ff-only origin codex/mobile-product &&
python3 ops/product_page.py --diagnose
```

`template_check` показывает `count`, область `scope`, ID/размер/хеши записей
и состояние: `no_active_override`, `active_override_matches_reviewed_source`,
`active_override_differs` или ошибку чтения. Текст шаблона и пароли в отчёт
не попадают. При SQL-ошибке выводятся только стадия и номер ошибки.
`source_files` отдельно сравнивает предоставленный файл с диском теста.

Если активный код отличается, экспортировать **один** эффективный шаблон
для разбора, сохранив БД и текущую витрину:

```bash
python3 ops/product_page.py --export-template
```

В `export.exported` будет путь к `active-product.twig` внутри
`test_frontend_backups/product-template-review-<дата>/`, вне публичной папки
и Git. Файл создаётся с правами 0600, каталог 0700. При изменении кода между
проверкой и экспортом чтение остановится. Для разбора можно передать этот
один файл из FTP; конфиги и дамп БД не нужны. После сверки источника обновляется
перечень изученных хешей, а не запись редактора шаблонов.

`--apply` сохраняет точные копии вне публичной папки в
`/home/lavkasp/lavka-speciy.com/test_frontend_backups/<rollback_id>/`.
Сохранить выданный `rollback_id`. Повторный запуск безопасен: текущие файлы
пропускаются. Пароли, содержимое конфигов и клиентские данные не выводятся.

После установки:

1. Если в `ocmod_refresh_required_for` указан `catalog/controller/product/product.php`,
   в **тестовой** админке обновить «Расширения → Модификаторы». Иначе выполняться
   продолжит старая сгенерированная копия контроллера, без новых подключений.
   Генерированные файлы вручную не редактировать.
2. Очистить HTML-кэш только `test.lavka-speciy.com`, при необходимости — штатный
   merged-кэш темы тестовой установки. Не сбрасывать все сайты аккаунта.
3. Открыть товар и выполнить Ctrl+Shift+R. Шаблон не менялся, отдельное
   редактирование/сохранение Twig не требуется.
4. В Network проверить успешную загрузку `lavka-mobile-product.css?v=1` и
   `lavka-mobile-product.js?v=1`. В консоли не должно быть новых JS-ошибок.

## Приёмка

- 320/390/432 px: порядок блоков, длинное название, отсутствие горизонтальной
  прокрутки, читаемость, метки, избранное и увеличение фото.
- Товар с одним фото и с галереей: миниатюры, свайп, увеличение и возврат.
- Смена веса/штук: цена, подпись «за …», количество и итог в корзине совпадают.
- Исходный select, дополнительные обязательные опции, периодичность, товар
  без цены и отсутствующий товар сохраняют штатные ограничения.
- После прокрутки вниз нижняя панель показывает текущую сумму/фасовку;
  покупка из неё создаёт один запрос. При ошибке нет автоматического повтора.
- Обязательное незаполненное поле показывает ошибку темы и остаётся доступным.
- Ссылка отзывов открывает штатную вкладку. У товара без отзывов нет
  приглашающего блока возле фото. Существующие вкладки/характеристики доступны.
- На 768 px и компьютере прежний вид; при изменении ширины поля остаются теми
  же и сохраняют выбранный вариант. Категория выглядит как одобренная версия.
- Меню, избранное, корзина и переход к оформлению. Реальный заказ/платёж
  или отзыв ради проверки интерфейса не отправлять.

Локально: 101 проверка Python/PHP/SQL и браузер с исходными обработчиками
Owl/Bootstrap, количества и корзины, с локальным HTTP вместо магазина.
Размеры 320/390/432/600/767/1280, radio/select, дополнительные поля, ошибки,
задержка 5,2 с, повторные клики, восстановление desktop. Это не подтверждение
действующего PHP/OCMOD/кэша хостинга — их проверяют на тесте после установки.

Воспроизведение браузерной проверки:

```bash
LAVKA_TEST_PRODUCT_TWIG=/path/to/reviewed/product.twig \
LAVKA_TEST_BOOTSTRAP_JS=/path/to/native/bootstrap.min.js \
python3 tests/check_mobile_product.py
```

Зависимости этих локальных тестов в магазин устанавливать не нужно.

## Откат

```bash
cd /home/lavkasp/lavka-frontend-work &&
python3 ops/product_page.py --rollback ID_ИЗ_ОТЧЁТА
```

Возвращается прежний контроллер, удаляются только новые файлы этого шага.
Если файл после установки изменили, откат остановится для ручного объединения.
Повторить штатное обновление тестовых модификаций и HTML-кэша.
БД и настройки меток при откате не затрагиваются. Производственный перенос
выполняет Игорь вручную после утверждения; тестовый установщик его не делает.
