# Установка меток в тестовый магазин

Версия для проверки от 28 октября 2026. Ветка `codex/product-tags`.
Установщик жёстко ограничен `test.lavka-speciy.com`, БД `lavkasp_test`,
`/home/lavkasp/lavka-speciy.com/test/` и отдельным `test_storage/`.

## Звёзды и отзывы: обновление после b2be391

В мобильных карточках категории и модулей добавлен блок из двух строк:
пять звёзд с непрерывным заполнением по средней оценке, затем значок чата и
**количество отзывов**. Например, оценка 4,8 заполняет полосу на 96%, во второй
строке отображается число 12, если опубликовано 12 отзывов. Числовая оценка
доступна в подсказке и описании для экранного диктора.

Если отзывов нет, звёзды не показываются: первая строка — значок чата и
«Добавить», вторая — «отзыв». Украинский вариант: «Додати / відгук».
Блок находится между ценой и корзиной; при недостатке места переносится под
название, перед ценой. Кнопка корзины сохраняет размер 36 × 36 px.
На компьютере карточки сохраняют штатный рейтинг темы.

Нажатие ведёт к вкладке отзывов товара; при нулевом количестве — к открытой
штатной форме. На странице товара сохраняются пять звёзд и подпись с числом
отзывов, заполнение звёзд и число синхронизируются с карточками.
Штатные правила гостевых отзывов, авторизации, CAPTCHA и модерации сохраняются.

Источник — только опубликованные строки таблицы `<prefix>review` (`status=1`).
Средняя оценка округляется до одного знака. Одна агрегирующая SQL-выборка
обслуживает весь пакет доступных товаров в уже существующем запросе свежих
меток; отдельного HTTP-запроса на каждую карточку нет. Тексты и авторы не
выдаются. Глобальное выключение отзывов магазина скрывает новые блоки.

При переходе с b2be391 меняются пять файлов: контроллер публичной выдачи
`catalog/controller/extension/module/lavka_product_tags.php`, подключающий
контроллер `catalog/controller/extension/module/uni_new_data.php`, скрипт
`catalog/view/theme/unishop2/js/lavka-product-tags.js` и два новых файла
`catalog/view/theme/unishop2/js/lavka-card-reviews.js`,
`catalog/view/theme/unishop2/stylesheet/lavka-card-reviews.css`.
**Новых изменений схемы или содержимого БД для отзывов нет.**
Старые хеши b2be391 включены в проверку обновления; метки и их настройки
сохраняются. Применить обычные pull/check/apply ниже, затем сбросить HTML-кэш
тестового домена и выполнить Ctrl+Shift+R. У новых CSS/JS версия URL v1,
у обновлённого скрипта меток — v2.

## Быстрый запуск через SSH

Команды выполняются в уже существующем Git-каталоге **вне папки магазина**.
Используется ранее настроенный ключ GitHub, ввод пароля в переписку не нужен.

```bash
cd /home/lavkasp/lavka-frontend-work &&
git remote set-branches --add origin codex/product-tags &&
git fetch origin &&
git checkout codex/product-tags &&
git pull --ff-only origin codex/product-tags &&
python3 ops/product_tags.py --check &&
python3 ops/product_tags.py --apply
```

Первое клонирование было с `--single-branch`: поэтому отдельная команда
добавляет новую ветку в список загрузки. При локальных изменениях Git может
остановиться: их сначала сохранить и разобрать, не выполнять принудительный
reset или checkout. В дальнейшем достаточно fetch, checkout и pull этой ветки.

`--check` читает конфиги без исполнения, проверяет реальные пути/ссылки,
обе БД-конфигурации, выбранную БД, тему, совместимость и точные хеши исходников.
Проверка БД только SELECT/SHOW, таблиц не создаёт. Пароли не выводятся.
Отчёт показывает `files_to_update`, `already_current`, состояние новых таблиц
и `ocmod_refresh_required_for`.

При `SOURCE_HASH_MISMATCH` ничего не форсировать. Передать указанный файл
**тестового** магазина для сравнения. Окончания строк LF/CRLF принимаются только
для заранее записанных вариантов. Настройки и пути рабочего сайта не нужны.
Если проверка обнаружит OCMOD, перекрывающий контроллер uni_new_data, она
останавливает установку до отдельного разбора; обходного `--force` нет.

`--apply` сначала проверяет весь комплект, затем создаёт/дополняет две таблицы
меток и устанавливает только изменившиеся файлы из manifest. Повторный запуск
не сбрасывает метки или оформление. Результат содержит `backup` и `rollback_id`.
Сохранить этот вывод. Копии исходников расположены вне публичной папки:
`/home/lavkasp/lavka-speciy.com/test_frontend_backups/<rollback_id>/`.

## Сразу после установки

1. Если `ocmod_refresh_required_for` содержит пути, в **тестовой** админке
   «Расширения → Модификаторы» обновить модификации штатной кнопкой.
   Редактировать `test_storage/modification/` вручную не нужно.
2. Очистить Twig-кэш через панель разработчика **тестовой** админки, если
   шаблоны кэшируются. Не заходить в редактор шаблонов и не удалять его
   переопределения вслепую. Очистку UniShop merged/generated выполнять только
   штатным механизмом тестовой установки при необходимости.
3. Один раз сбросить HTML-кэш **только test.lavka-speciy.com**, чтобы категории
   получили новые подключения JS/CSS. Если хостинг использует общий LiteSpeed
   для нескольких сайтов, выбирать очистку тестового домена, а не всего аккаунта.
4. Перезагрузить админский список и категорию с Ctrl+Shift+R. В консоли браузера
   не должно быть PHP/JS-ошибок. POST маршрута
   `extension/module/lavka_product_tags/info` должен отвечать JSON с `products`.

После первого обновления страницы скрипт запрашивает актуальные метки пакетно
(до 60 уникальных товаров в запросе), даже когда HTML взят из кэша. Он также
обновляет метки при возвращении фокуса на вкладку и появлении новых карточек.
Сохранение галочки дополнительно вызывает установленный штатный путь очистки
LiteSpeed для товаров/категорий. Отсутствие LSCache не мешает сохранению.
Если запрос свежих меток не сработал, остаётся исходная серверная разметка;
ошибку транспорта надо исправить, а не считать кэш гарантированно очищенным.

## Как пользоваться

«Каталог → Товары»: новая колонка **Метки** после названия товара. В строке
три ручные галочки, автоматические статусы Топа и «Новинки», сообщение о сохранении.
Страница, фильтры и выбор товаров для массовых операций сохраняются.
Галочки меток не входят в список `selected[]`.

Галочка сохраняется **сразу**, без общей кнопки сохранения товара. Вкладка
«Данные» формы товара содержит такой же блок с тем же поведением. Отмена
редактирования остальных полей не отменяет уже сохранённые метки. Для нового
товара блок недоступен до первого сохранения самого товара.

Кнопка «Метки товаров» сверху списка или шестерёнка в заголовке колонки
открывает оформление всех пяти типов:
включение, названия RU/UA, фон, цвет текста, порядок и срок «Новинки».
Глобальное выключение типа скрывает его на витринах, сохраняя назначения.
Права используются штатные: `access/modify catalog/product`; расширять
права группы или менять таблицы пользователей не требуется.

При конфликте «Данные изменены в другом окне» обновить список и повторить
осознанный выбор. Автоматических повторов записи нет. При сетевой ошибке
также сначала обновить страницу: сервер мог успеть сохранить изменение.

## Начальные значения и совместимость

- «Новинка» переносит при первом запуске включение, срок и цвета из UniShop2.
  Дальнейшая настройка пяти маркетинговых типов — на новой странице оформления.
  Дата доступности товара + срок; редактирование, цена и остаток срок не меняют.
- «Топ продаж» (`hit`) определяется суммой проданных упаковок в завершённых
  заказах текущего магазина за всё время, от 11 по умолчанию. Ручные назначения,
  текст MPN и настройка штатного «Лидера продаж» не обходят этот критерий.
  Включение типа, его название, цвет и порог меняются на новой странице.
  Отменённые, возвращённые и ожидающие заказы не считаются, если их статусы
  не включены владельцем в настройку завершённых заказов. При пустой настройке
  метка выключена, в админском блоке показано предупреждение.
  Агрегат продаж кэшируется до 30 минут; изменение порога применяется сразу
  к имеющемуся агрегату. После изменения статусов настройка учитывается заново.
- «Свежий помол», «Наша марка», «Эксклюзив» изначально не назначены.
- Включённые штатные UPC/EAN/JAN/ISBN/SKU и произвольный MPN сохраняются.
  Числа 1111–4444 с тестовых скриншотов останутся, пока их значения или показ
  не отключены вручную. Это не новые маркетинговые метки.
- «Акция» и бонусные стикеры остаются в штатной логике темы. Для них не
  добавляются маркетинговые галочки.
- Все заданные метки выводятся; при пяти метках и нескольких рядах фасовок
  высота фото на узком экране увеличивается, чтобы они не перекрывались.
  Фото в этом режиме заполняет увеличенную область с кадрированием.
- Никаких изменений цены, расчёта фасовки, количества в корзине или срока
  серверного добавления в корзину этот выпуск не вводит.

## Приёмка на тесте

- Товар 816: назначить три ручные метки, проверить автоматические Топ и
  «Новинку», RU/UA, порядок и HEX. «Новинка» требует даты внутри периода, Топ —
  количества продаж не ниже порога. Глобальное выключение типа скрывает его.
- Изменить цвета UPC/EAN в UniShop2: сверить фон и текст категории и товара;
  для пяти маркетинговых типов использовать новую страницу оформления.
- Проверить обычную и кэшированную категорию, страницу товара, поиск и «Новинки».
  Две карточки одного товара должны получить одинаковые метки.
- Сверить количество продаж с завершёнными заказами: 10 упаковок при пороге
  11 не дают Топ, 11 дают; один заказ с 11 упаковками тоже даёт. У нескольких
  подходящих товаров метка отображается независимо от места в рейтинге.
  Для проверки не создавать настоящие заказы: можно временно изменить порог
  под существующие тестовые данные, а затем вернуть 11.
- Поменять MPN или старый ручной флаг: автоматический Топ не должен меняться.
  При отсутствии статусов завершённого заказа проверить предупреждение.
- Изменить одну и ту же галочку в двух вкладках: второе сохранение со старой
  ревизией показывает конфликт. Разные метки не затирают друг друга.
- Проверить сохранение основной формы, копирование/удаление **тестового** товара,
  фильтры, сортировку и пагинацию списка. Пользователь без modify не может писать.
- Телефон 320/390/432 px и компьютер: меню, фото, все метки, избранное, фасовки,
  цена, добавление выбранного веса в корзину и переход к оформлению.
  Реальный заказ/уведомления не отправлять ради проверки интерфейса.
- У товара с опубликованными отзывами сверить число с админкой и страницей
  товара, проверить заполнение пяти звёзд. Непроверенные отзывы не считаются.
  Для товара без отзывов проверить ровно две строки «Додати / відгук» и
  переход к открытой форме. Отправлять новый отзыв для этой проверки не нужно.
- При изменении фасовки, длинной цене, подгрузке категории и в карусели блок
  не перекрывает цену/корзину. Переключить RU/UA и проверить подписи.
  Если отзывы глобально отключены в настройках магазина, блоки не отображаются.

Локально выполнены 88 автоматических проверок Python/PHP/SQL, шесть
браузерных сценариев меток, шесть сценариев отзывов и 11 проверок штатной
корзины/фасовок с новым блоком. HTTP имитируется, проверки на хостинге ещё
предстоят. Файлы: `tests/test_*.py`, `tests/check_product_tags.py`,
`tests/check_card_reviews.py`, `tests/check_mobile_cards.py`. Для проверки
отзывов переменная `LAVKA_TEST_BOOTSTRAP_JS` указывает на неизменённый
`catalog/view/theme/unishop2/js/bootstrap.min.js` из полученной копии магазина.
Локальный SQL-движок и браузерные зависимости не устанавливались в магазин.

## Откат

Использовать **rollback_id именно установки меток**, а не старого мобильного
выпуска:

```bash
cd /home/lavkasp/lavka-frontend-work &&
python3 ops/product_tags.py --rollback ID_ИЗ_ОТЧЁТА
```

Откат проверяет хеши и восстанавливает реальные байты исходников, удаляет
только добавленные этим шагом файлы. Если установленный файл позже изменили,
автоматический откат остановится для ручного объединения. После отката
повторить штатное обновление тестовых модификаций/Twig/HTML-кэша.

Две таблицы меток и добавленный `min_sales` **сохраняются при откате**, чтобы не потерять сделанные
назначения и выбранный порог. Предыдущий выпуск 38e56b3 игнорирует
дополнительный столбец и снова использует сохранённые ручные назначения.
При повторной установке
данные доступны снова. Дамп БД и откат существующих товаров не требуются.
Не удалять таблицы вручную без отдельного решения и копии новых назначений.

Старый пакет `handover/releases/lavka-mobile-cards-1.0.0-rc1.zip` этим выпуском
не заменяется и новых меток не содержит. Комплект меток сначала проходит
приёмку на тесте; перенос на рабочий сайт затем выполняет Игорь вручную.
