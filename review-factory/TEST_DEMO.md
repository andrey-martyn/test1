# Демо-показ в TEST-магазине ocStore / UniShop2

При смене каталогов сначала прочитать [общий контракт](../HOSTING_PATHS.md).
Команды ниже используют прежние пути до переключения. После переноса сохранить
существующую синтетическую базу/модерацию и обновить `runtime`/`data` в
`test/system/library/review_factory_demo_config.php` штатным обновлением
собственных файлов (`demo-install`) с уже перенастроенным существующим `--data`.
Если модуль ещё не установлен, смена путей не является командой его установки.

Это отдельное расширение для **test.lavka-speciy.com / lavkasp_test**.
Оно показывает одобренные синтетические записи отдельным блоком на карточке
и отдельно подписанные демо-оценки в каталоге. Обычная лента, количество,
покупательский рейтинг, JSON-LD и фиды магазина не изменяются.

## Установка через WebSSH

```bash
cd /home/lavkasp/lavka-speciy.com/analytics-app &&
git switch analytics-demo &&
git pull --ff-only &&
/usr/local/php82/bin/php review-factory/php/bin/console.php demo-install \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
```

Ожидается `test_demo_files_ready`, `environment:test`, `native_review_writes:false`.
Команда проверяет текущую TEST-конфигурацию, создаёт таблицы решений в собственной
SQLite и копирует десять файлов нового расширения в корень TEST-магазина.
`config.php`, корневой `index.php`, установленная тема, существующие расширения,
учётные записи и пароли не переписываются. Из CLI нет подключения к MySQL.
Повторный запуск обновляет только файлы с маркером нашего расширения;
коллизии с чужими файлами и символьные ссылки отклоняются.

Затем в **админке TEST-магазина**:

1. «Расширения → Расширения», выбрать тип **«Модули»**.
2. Найти **«Комбайн · Демо-отзывы TEST»** (в украинском интерфейсе —
   «Комбайн · Демо-відгуки TEST»), нажать зелёный **«+ Установить»**.
3. Нажать **карандаш «Редактировать»**. Откроется отдельный список модерации.
   После обновления админки он доступен и слева: **«Демо-отзывы TEST»**.
4. Одобрить **одну** запись кнопкой «Одобрить для демо-витрины» и открыть
   её товар по ссылке в этой же строке. Проверить карточку и каталог, затем
   можно модерировать следующие записи.

При установке через админку регистрируются два собственных события:
`catalog/controller/common/header/before` для витрины и
`admin/view/common/column_left/before` для пункта меню. Включается настройка нашего модуля
и выдаются права на его страницу текущей группе администратора. Это штатные
таблицы настроек/событий/прав расширений; таблица `oc_review` не используется.
Другим группам модераторов при необходимости выдать `access` и `modify` на
`extension/module/review_factory_demo` через обычные группы пользователей.

Модуль **не нужно добавлять в макеты**, загружать ZIP или обновлять OCMOD.
Вызов как модуля макета возвращает пустой результат и не подменяет страницу JSON.
Старый архив ручных авторских отзывов из `LEGACY.md` для этого сценария не нужен.
Если после установки видна старая копия страницы, выполнить **Purge All LiteSpeed
Cache** в админке TEST и обновить браузер. Ресурсы нового расширения имеют версию
по хешу содержимого.

## Работа и модерация

- Автор работает по прежнему адресу `https://test.lavka-speciy.com/review-workshop/`.
  Вход `admin-review` и прежние личные аккаунты сохраняются.
- Сохранённая карточка, включая ранее сохранённые записи, попадает в ожидание.
  Черновики и пропущенные карточки на модерацию не поступают и не показываются.
- Только специалист с правом `modify` нового модуля может одобрить запись.
  Проверяется авторизация ocStore и `user_token`; решение связано с точной
  версией сохранённой записи. После изменения версии нужно новое одобрение.
- «Не показывать» отклоняет запись или снимает ранее одобренную. Следующий запрос
  витрины уже не получает её; для уже открытой страницы требуется обновление.
- В истории Комбайна видны состояния «ожидает модерации / одобрено для демо /
  не показывать». Показанные записи не смешиваются с покупательской лентой.
- Каждая публичная запись имеет пометку **«ДЕМО · синтетическая запись, не отзыв
  покупателя»**, подпись «Вымышленный автор», «Модельная дата» и при наличии город.
  Частные модельные группы «Проверенный отзыв / Без регистрации» на витрину
  не выводятся. Демо-среднее считается только по одобренным синтетическим
  записям. Общий эксперимент «магазин + синтетика» остаётся внутри Комбайна.
  В каталоге написано «ДЕМО · синтетические оценки» и отдельно
  «Отдельно от оценок покупателей».

Для модерации или показа **не нужен новый cron**. Данные читаются непосредственно
из отдельной `synthetic-reviews.sqlite3` только на чтение. Решения и отдельный
аудит находятся там же в `demo_decisions` и `demo_events`. Native `review_id`,
учётные записи покупателей и их персональные данные не копируются.

## Ограничения и изоляция

Реальная БД должна называться `lavkasp_test`, HTTP-host — строго
`test.lavka-speciy.com`; дополнительно проверяются TEST-манифест и окружение
Комбайна. Скопированное на рабочий домен расширение не загружает демо-данные.
Режим переноса/maintenance также блокирует чтение и новые решения.

Витрина получает только одобренные версии записей для текущих видимых товаров
магазина. API принимает до 40 ID, отдаёт сводки каталогу и до 20 текстов одного
товара. Длинный текст отображается фрагментом до 3000 символов с подписью.
PHP 7.3 читает SQLite через `SQLITE3_OPEN_READONLY` и `query_only`; модерация
пишет только в отдельную базу Комбайна. Заголовки API: `no-store`, `nosniff`,
`noindex,nofollow,noarchive`. Заголовок исключения из индексации добавляется
также в TEST-страницы при включённом событии.

JS добавляет новые узлы DOM и не меняет покупательские звёзды/счётчики,
поля `itemprop`, JSON-LD или native review-модели. Текст выводится через
`textContent`; отказ демо-API оставляет обычную витрину работоспособной.
Модуль ищет обычные карточки OpenCart/UniShop2 `.product-thumb`, числовой
`data-product-id`, `cart.add(ID)` или ссылку `product_id`; для карточки товара —
`#product input[name=product_id]`. Ajax-карточки поддерживаются.

Файлов конкретной установленной UniShop2 в репозитории нет. Проверены native
контроллеры с тестовыми зависимостями и типовая разметка на 390/1440 px;
первый реальный показ на хостинге нужно проверить на одной одобренной записи.
Требуются уже используемые PDO SQLite и SQLite3 для веб-PHP; версию PHP и
тариф менять не требуется.

Удаление модуля через список расширений выключает событие и показ, сохраняя
закрытые записи и решения. Повторная установка сохраняет модерацию.
Резервная копия Комбайна включает решения вместе с основной синтетической базой.
Перенос в production эту отдельную базу не копирует, демо-расширение туда
не устанавливается. После физического перемещения TEST-каталогов повторить
`demo-install`, чтобы обновить локальные пути нового расширения.

## Проверки

`php/tests/demo.php`: установка без изменения корневых файлов, первичное ожидание,
одобрение, скрытие, версия записи, журнал решений, блокировка production и
переноса, отсутствие native-заданий, повторная установка и коллизии.
`php/tests/demo_native.php`: отдельные catalog/admin-контроллеры, права,
CSRF, видимость товаров, событие OpenCart 3, безопасные URL, выключение и
отдельная проверка production-БД. `php/tests/demo_browser.py`: явные пометки,
разделение рейтингов, неизменность native JSON-LD, экранирование текста,
корзина, Ajax-карточки, удаление одобрения и отказ API. Используются только
синтетические локальные фикстуры; реальные клиентские базы не нужны.
