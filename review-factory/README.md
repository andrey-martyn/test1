# Комбайн отзывов «Лавочки»

Самостоятельный PHP-модуль для команды магазина. Авторы входят под личными
учётными записями, получают товар, пишут материал и отправляют его. Фоновая
команда создаёт **один штатный отзыв ocStore со статусом 0**. Проверка текста
и активация выполняются в существующей админке: «Каталог → Отзывы».
Доступ к аналитике и админке магазина авторам не нужен.

Первая установка предназначена для **TEST / lavkasp_test**. Рабочий магазин
не изменяется при установке TEST-модуля. Перенос описан в [MIGRATION.md](MIGRATION.md).
Новые файлы находятся в `review-factory/`; действующая аналитика не изменена.
База, пароль и конфигурация аналитики не перенастраиваются.

## Принятые правила

Разделы 3, 7 и 8 приложенного ТЗ используются как согласованная модель авторства:
реальные сотрудники, явная связь с магазином, фактическая дата публикации,
собственная оценка 1–5. Историческая дата опыта — отдельное поле. Случайные
покупатели, вымышленные города, задние даты и подбор звёзд для целевого рейтинга
не используются. Тексты конкурентов — короткие справочные выдержки со ссылкой;
чужой опыт не публикуется автоматически от имени сотрудника.

Оценки команды видны в обычной ленте отзывов, но OCMOD исключает их из
покупательского среднего и количества оценок в стандартном каталоге OpenCart.
Ядро и шаблоны магазина напрямую не переписываются. **Установленную UniShop2,
другие расширения, JSON-LD и используемые фиды необходимо проверить на TEST:**
их файлов в репозитории нет, поэтому готовность всей реальной витрины не заявляется.

## Что работает

- Личные пользователи, роли администратора комбайна, автора и редактора.
  Автор видит свои назначения и материалы; редактор может смотреть материалы
  команды. Редактор комбайна не активирует отзывы на сайте.
- Пакеты из 1, 5 или 10 товаров, исключительное назначение автору, ручная
  корректировка приоритета с причиной, снятие назначения администратором.
- Черновики на сервере, конфликт версий вкладок, собственные звёзды,
  настроение, фактический город и дата опыта, просмотр перед отправкой.
- Очередь отправки, безопасные повторы после сбоя, штатная модерация, чтение
  текущего статуса магазина и журнал действий. Удалённая в магазине запись
  не создаётся повторно автоматически.
- Справка о товаре, последние 20 опубликованных материалов магазина, четыре
  источника конкурентов, до трёх обезличенных выдержек на источник.
- Адаптер читает подтверждённые сопоставления существующего мониторинга через
  SQLite в режиме только для чтения. Сбор отзывов — дополнительная задача:
  прежний ценовой парсер сам этих сведений не собирает.
- JSON-LD Product и однозначная товарная микроразметка: `reviewCount`, оценка
  на шкале 1–5, выдержки. `ratingCount` не подменяет число текстовых отзывов.
  Неизвестное значение — NULL, подтверждённый ноль — 0; ошибки не стирают
  прежний успешный результат. Сайты: Deluxe, Spicery Shop, Банка Спецій, specii.
- Каждая успешно прочитанная карточка ждёт 24 часа. Ограничены пакет, время,
  размер ответа; действуют HTTPS, robots.txt, DNS/SSRF-проверки и паузы
  существующей HTTP-библиотеки. CAPTCHA и клиентский JavaScript не обходятся.
- Вес очереди: конкуренты 55, недостаток материалов 20, товары в заказах
  за 90 дней 15, просмотры за 30 дней 10. Неизвестные факторы исключаются
  с пересчётом весов. `competitor_ref` — среднее двух наибольших известных
  свежих значений; при одном источнике используется только он.
- Логарифмическая нормализация конкурентного сигнала с ограничением p95;
  целевой ориентир 3–10 материалов и баланс глубины 40/40/20 — подсказки,
  а не квоты. Стартовая пауза после отправки — 14 дней.
- Темы и положительные/критические упоминания определяются простыми словарными
  правилами и явно помечены как подсказки. Платный ИИ не подключён.
- Статистика своих/командных материалов, глубины, настроений, авторов,
  приоритетов. Native status=0 означает ожидание модерации, а не доказанный
  отказ: отсутствие отдельного признака отклонения не заменяется догадкой.
- Мобильный интерфейс 390 px; на телефоне форма и справка переключаются без
  потери текста. Ctrl+Enter отправляет; Ctrl+S сохраняет вне текстовых полей;
  Alt+стрелки переключают назначенные товары вне полей ввода.

## Границы первого пакета

Доступность полей на всех четырёх реальных сайтах из хостинга ещё не подтверждена.
Если разметки Product/Review нет в первичном HTML, будет неизвестное значение
или ошибка, а не выдуманное число. Доработка конкретного сайта требует его
реального ответа; синтетические проверки этого не заменяют.

Просмотры за последние 30 дней не подключены: накопительный `product.viewed`
не выдаётся за месячную статистику. Очередь использует оставшиеся факторы.
Импорт каталога ограничен 10 000 товаров, публичных отзывов — 100 000;
превышение не публикует частичный новый снимок. Архив истории конкурентов
содержит данные наблюдений, а не полные HTML-страницы.

Передача выполняется отдельным PHP 8.2 CLI. Команды читают реквизиты из
локального config.php выбранной копии магазина как литералы, **не исполняют
этот PHP и не выводят секреты**. Проверяются ожидаемая БД и локальное соединение.
Для известного `lavkasp.mysql.tools` используется проверенный 127.0.0.1 без
изменения файла конфигурации. Веб-процесс читает только свою закрытую SQLite.

## Установка на TEST

Сначала код должен попасть в клон ветки `analytics-demo` на хостинге.
Публикация кода в Git сама не устанавливает модуль. Новая самостоятельная папка:

| Назначение                             | Путь                                                              |
| -------------------------------------- | ----------------------------------------------------------------- |
| Код                                    | `/home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php` |
| Публичный вход                         | `/home/lavkasp/lavka-speciy.com/test/review-workshop`             |
| Закрытые данные                        | `/home/lavkasp/lavka-speciy.com/review-factory-private-test`      |
| Существующий мониторинг, только чтение | `/home/lavkasp/lavka-speciy.com/analytics-private-test`           |

Предлагаемый URL: `https://test.lavka-speciy.com/review-workshop/`.
DNS, новый поддомен и изменение версии PHP не нужны. Папка установки должна
быть свободна; установщик откажется заменять существующее содержимое.

Из WebSSH, после получения кода:

```bash
cd /home/lavkasp/lavka-speciy.com/analytics-app
/usr/local/php82/bin/php review-factory/php/bin/console.php setup \
  --shop-root /home/lavkasp/lavka-speciy.com/test \
  --webroot /home/lavkasp/lavka-speciy.com/test/review-workshop \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --analytics-data /home/lavkasp/lavka-speciy.com/analytics-private-test \
  --url https://test.lavka-speciy.com/review-workshop \
  --language auto --statuses analytics
```

`auto` читает язык текущего магазина. `analytics` использует сохранённые
`report.status_ids` аналитики; при отсутствии настройки — правило исключения
отмен/возвратов по названиям статусов. Можно явно задать `--language ID`
и `--statuses ID,ID`. Список находится в закрытом instance.json и должен
соответствовать правилам учитываемых заказов магазина.

Создание первого **администратора комбайна**, отдельно от ocStore:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php user \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --login tanya --name Таня --staff-role хозяйка --role admin
```

Пароль от 12 символов вводится скрыто дважды в WebSSH. Не передавайте его в
аргументах или чате. Остальных авторов можно создать в разделе «Команда и
настройки». Их пароли и доступ не дают прав в аналитике или магазине.

Первый импорт, без записи в магазин:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php sync --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
/usr/local/php82/bin/php review-factory/php/bin/console.php collect --data /home/lavkasp/lavka-speciy.com/review-factory-private-test --limit 5 --seconds 55
```

## Расширение штатной модерации

Архив `lavka-review-factory.ocmod.zip` содержит install.xml и два новых файла
административного расширения. **Только на TEST, в таком порядке:**

1. Загрузить архив через установщик расширений ocStore.
2. В списке модулей установить «Комбайн отзывов — Лавочка». Именно этот шаг
   создаёт `oc_review_factory_meta`, `oc_review_factory_config` и события даты.
3. После создания таблиц обновить модификаторы. Нельзя активировать SQL-фильтр
   раньше создания таблицы метаданных: запрос каталога обращается к ней.
4. Открыть настройки модуля. Они сверяют наличие фильтра среднего (`r1`) и
   количества (`r2`) в сгенерированном model/catalog/product.php. При успехе
   передача на `lavkasp_test` разрешается для тестирования.
5. Отправить один настоящий тестовый материал из комбайна, запустить dispatch,
   убедиться в status=0 в «Каталог → Отзывы». Повтор dispatch не создаёт дубль.
6. Проверить подпись, текст и после активации — дату, звёзды и отделение
   рейтинга на карточке, в категории, JSON-LD и активных фидах UniShop2.
   Записать результат в настройках расширения.

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php dispatch --data /home/lavkasp/lavka-speciy.com/review-factory-private-test --limit 3
```

Перед каждой отправкой CLI повторно читает сгенерированный фильтр из
DIR_STORAGE/modification; исчезновение стандартной защиты останавливает передачу.
Если DIR_STORAGE в config.php задан выражением вместо строкового литерала,
нужна отдельная адаптация диагностики. Парсер не исполняет конфиг ради этого.

Совместимость OCMOD проверена на исходнике стандартного OpenCart 3.0.2.0.
Встроенная проверка не доказывает отсутствие стороннего прямого SQL в UniShop2
или фидах. При обнаружении такого запроса адаптировать соответствующее расширение
на TEST, прежде чем включать передачу на рабочем сайте.

Не удалять метаданные/фильтр, пока существуют авторские оценки: они составляют
одну интеграцию. Установка/обновление расширения не включены в обычное обновление
аналитики и не выполняются автоматически.

## Фоновые задания

Это отдельные задачи модуля. Действующие cron продаж, цен и мониторинга сохранить.
Уже работающую задачу не дублировать. В ADM.TOOLS расписание задаётся отдельно,
в поле команды — строка без `cd`, `&&` и перенаправлений.

Ежедневно, например 04:10 по **часовому поясу планировщика хостинга**:

```text
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php/bin/console.php sync --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
```

Сбор очередного ограниченного пакета каждые пять минут (`*/5 * * * *`):

```text
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php/bin/console.php collect --data /home/lavkasp/lavka-speciy.com/review-factory-private-test --limit 12 --seconds 45
```

Это не повторное чтение каждой карточки раз в пять минут: успешная карточка
становится доступна через 24 часа. Для большого каталога надо сопоставить объём
очереди и измеренную скорость; интервал пакетов можно уменьшить без изменения
суточного интервала карточки. Начальный бюджет не обещает обход произвольного
количества товаров за сутки. Старый мониторинг и сбор отзывов имеют независимые
лимиты; выбирать разнесённые минуты запусков после измерения нагрузки.

Передача подготовленных материалов каждую минуту (`* * * * *`):

```text
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php/bin/console.php dispatch --data /home/lavkasp/lavka-speciy.com/review-factory-private-test --limit 3
```

Одна блокировка исключает пересечение собственных CLI-задач. Отправка не
публикует запись; обработка модерации остаётся человеку в ocStore.
Расписание пользователем пока не настроено и этим пакетом не подтверждается.

## Обновление и копии

Launcher читает PHP, HTML и JS/CSS из клона; версия ресурсов зависит от содержимого.
После появления изменений в `analytics-demo` достаточно `git pull --ff-only`
для самого комбайна. Setup и создание пользователей повторять не надо.
Правила обновления действующей аналитики остаются прежними.

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php status --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
/usr/local/php82/bin/php review-factory/php/bin/console.php backup \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --destination /home/lavkasp/lavka-speciy.com/review-factory-backup-YYYYMMDD
```

Backup создаёт согласованный новый SQLite-снимок, проверяет quick_check,
копирует instance.json и исключает сессии/попытки входа. Назначение должно быть
новым закрытым каталогом вне публичных корней. Не загружать его в Git или чат.
Для полного восстановления интеграции нужны также обычные закрытые копии
магазинных `review`, `review_factory_meta`, `review_factory_config` и расширения.
Самостоятельного удаления старых копий нет.

Для восстановления личного пароля: `console.php reset-password --data … --login …`;
ввод скрытый, прежние сессии данного автора отзываются.

## Проверки разработки

Python/Playwright и Docker используются только разработчиком, на хостинг не нужны.
PHP-проверки: `php/tests/core.php` на 7.3/8.2, `php/tests/deployment.php` на 8.2.
MySQL: `php/tests/mysql.php` на отдельной синтетической БД, native MyISAM и
метаданные InnoDB; тест требует закрытый файл `/test-secrets/mysql.env`.
`php/tests/seed.php` создаёт только новую синтетическую SQLite, пароль берёт
из `RF_TEST_PASSWORD`; `browser.py` проверяет HTTP/CSRF/роли и 390/1440 px.
Реальные клиентские данные для этих проверок не использовались.
