# Комбайн отзывов «Лавочки»: закрытый TEST-стенд

Основной экран после входа — очередь товаров с автоматически заполненными
тестовыми карточками. Раздел ответов магазина для тестовых учётных записей
убран. Вход `admin-review`, существующие пароли и сохранённые материалы остаются.

Это генератор синтетических данных для проверки интерфейса. Карточки явно
помечены «ТЕСТОВЫЕ ДАННЫЕ · не отзыв покупателя». Они доступны после входа
в закрытом предпросмотре внутри Комбайна. В `oc_review` TEST-магазина или
рабочего магазина они не записываются, механизмов их публикации и экспорта нет.

## Обновление уже установленного TEST

В WebSSH выполнить:

```bash
cd /home/lavkasp/lavka-speciy.com/analytics-app &&
git pull --ff-only &&
/usr/local/php82/bin/php review-factory/php/bin/console.php simulation-status \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
```

Ожидаемый результат: `private_simulation_ready`, `shop_publication:false`.
Открыть **https://test.lavka-speciy.com/review-workshop/**, обновить страницу
и войти существующим `admin-review`. Повторный `setup`, новый пароль,
OCMOD или новый cron для сохранения тестовых карточек не требуются.
Ресурсы загружаются из `review-factory/php/static/` с версией по хешу.

При первом обращении TEST-аккаунты переводятся в режим `testing`. Прежние
незавершённые задания отправки и ответов приостанавливаются. Черновики, тексты,
пароли и аудит сохраняются. Уже существующие отзывы магазина не изменяются.
Старые `dispatch`/`reply-worker` при отсутствии подходящих ручных аккаунтов
возвращают состояние отключённого рабочего места до подключения к MySQL.

## Сценарий работы

1. Очередь выдаёт один товар либо пакет из 5 или 10; товар закрепляется за
   оператором, коллега не получает ту же активную карточку.
2. Сразу заполнены **текст**, вымышленное имя или имя с фамилией, модельная
   группа, звёзды, настроение, город и дата. Текст — явно помеченный шаблон
   для проверки формы; платная генерация или внешний сервис не используются.
3. Текст можно изменить и сохранить черновиком. Автополя закреплены за
   карточкой, не выбираются вручную и не меняются после перезагрузки.
4. «Сохранить тестовый отзыв» сохраняет запись в отдельной закрытой базе
   и открывает следующий товар. «Тестовые записи» показывает историю и
   закрытый предпросмотр с пометкой TEST у каждой записи. В пакете доступна
   кнопка «Сохранить весь тестовый пакет»: ручной ввод текста не требуется.

Описание и характеристики свернуты. Интерфейс проверяется на 390 и 1440 px.
Права доступа, CSRF, проверка владельца карточки и контроль версии черновика
работают на сервере. Предпросмотр экранирует HTML и требует авторизации;
страницы возвращают `X-Robots-Tag: noindex, nofollow, noarchive` и `no-store`.

## Автоматические правила

- Имена — отдельные вымышленные наборы, без чтения имён клиентов магазина.
  Примерно поровну только имя и имя с фамилией.
- На каждые 100 выданных карточек — 15 модельных гостей и 20 без города.
  В малом пакете доли округляются; пропуски остаются в учёте выдачи.
- Оценка выбирается из 3/4/5 по среднему **синтетических** сохранённых записей
  этого товара с ориентиром 4,4–4,8. Первая целая оценка не может попасть
  в этот диапазон: ставится ближайшая, далее баланс корректируется.
- Настроение: 3 — нейтральное, 4 — хорошее, 5 — отличное.
- Даты: с 2022-01-01 до текущего дня, максимум 2026-12-31. Сначала выбирается
  менее заполненный модельный год, затем месяц и свободный промежуток дат.
  Реальные даты отзывов покупателей не меняются и не используются для имитации.
- Приоритет: существующие веса конкурентного ориентира, дефицита, продаж и
  просмотров; дефицит рассчитывается по числу тестовых записей. Неизвестные
  факторы исключаются с перенормировкой весов. Активные товары в наличии
  проходят раньше; после сохранения сначала выдаются другие товары.

## Как проверить среднее

Карточка показывает **среднее этого товара** по сохранённым синтетическим
записям, отдельно — прогноз после сохранения текущего черновика. Если у товара
ещё нет сохранённых записей, среднее `—`, а не ноль. После сохранения очередь
открывает другой товар; его показатели считаются заново. Прогноз не записывается
как готовый отзыв. Фактические оценки покупателей и оценки конкурентов не
участвуют в модельном среднем.

В «Тестовых записях» есть общее среднее по всем сохранённым записям и таблица
по товарам: сумма звёзд ÷ количество записей. Общее среднее взвешено числом
записей, а не является средним арифметическим средних товаров. Отображение —
до двух знаков после запятой. Кнопка «Обновить данные» перечитывает показатели
и локальные источники, не меняя несохранённый текст и закреплённые автополя.

Диагностика без вывода текстов отзывов или паролей:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php simulation-status \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
```

`saved_stats` содержит число записей, сумму звёзд и среднее; `per_product` —
до 20 товаров с такими же показателями. Первая запись каждого товара может
дать среднее 5: целая единственная оценка не попадает в диапазон 4,4–4,8.
Следующие карточки балансируются по уже сохранённым записям этого товара.

## Данные и ссылки аналитики

«Источники мониторинга» стоят первыми в подсказках и развёрнуты по умолчанию.
Показываются подтверждённые карточки именно текущего товара, время обновления
ссылок, состояние сбора, распознанное число отзывов/оценка источника и до трёх
сохранённых фрагментов. Эти фрагменты экранируются как текст. Если соответствий
нет, чужие товары не подставляются. Пустой список после успешного импорта
отличается от состояния, когда ссылки ещё не загружали или обновление не удалось.

Основной каталог/очередь и подтверждённые страницы конкурентов находятся
в частной `factory.sqlite3`. Ссылки можно обновить **отдельно от MySQL магазина**:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php matches-sync \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --analytics-data /home/lavkasp/lavka-speciy.com/analytics-private-test
```

Исходный `competitors.sqlite3` открывается `SQLITE3_OPEN_READONLY` и
`PRAGMA query_only=ON`, с ожиданием блокировки до пяти секунд. Выбираются только
`enabled=1`, `kind=product`, `match_confirmed=1`, непустой `match_group` и четыре
конкурента. Цена и наличие у конкурента не являются условиями импорта.
`--analytics-data` сохраняет проверенный путь в `instance.json` Комбайна;
последующие вызовы `matches-sync` могут не указывать его. Исходная база и
конфигурация аналитики не изменяются.

Результат `matches_synced`: `confirmed_pages` — найденные подтверждённые
страницы, `mappings` — связи товар/магазин после устранения дубликатов,
`products_with_sources` — охваченные товары. `unknown_product_pages` означает,
что соответствующий ID отсутствует в каталоге Комбайна, `invalid_group_pages` —
нераспознанный ключ, `duplicate_pages` — дополнительные страницы той же пары.
Для отсутствующего каталога сначала требуется обычная `sync`; не связывать
товары предположительно по совпавшему имени.

После загрузки ссылок запустить первую небольшую порцию сбора:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php collect \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --limit 5 --seconds 55
```

Ссылки видны сразу после импорта; числа и фрагменты появятся только после
успешного чтения страниц. Сбор ограничен временем, размером ответа,
robots.txt и паузой между запросами; неизвестное значение остаётся неизвестным.
Не обещать успешный сбор с реального сайта по результатам локальных фикстур.

Для регулярного обновления при отсутствии существующей такой задачи добавить
в ADM.TOOLS **одну** команду каждые 15 минут:

```text
/usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php/bin/console.php matches-sync --data /home/lavkasp/lavka-speciy.com/review-factory-private-test && /usr/local/php82/bin/php /home/lavkasp/lavka-speciy.com/analytics-app/review-factory/php/bin/console.php collect --data /home/lavkasp/lavka-speciy.com/review-factory-private-test --limit 5 --seconds 55
```

Если уже есть cron `collect` для этой установки, дополнить его `matches-sync`,
а не создавать дубликат. Сам сборщик пропускает свежие успешные страницы
до следующей суточной проверки; ошибки пробует повторить через шесть часов.
Обновление списка целиком убирает снятые подтверждения из интерфейса и сбора.
Наличие расписания на хостинге нужно проверить отдельно.

Штатная полная команда `sync` читает каталог магазина и ссылки аналитики:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php sync \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test
```

Её нужно запускать если каталог магазина требует обновления.
Путь аналитики берётся из существующего `instance.json`; подключение магазина
и пароли не перенастраиваются. Источники: Deluxe, Spicery Shop, Банка Спецій,
specii.in.ua. `target_id` не используется как ID товара магазина, связь идёт
по строковому `match_group=lavka-{product_id}`. Снятые подтверждения обновляются
при полном перечитывании ссылок. Ошибка чтения и неизвестное число отзывов
не заменяются нулём. Отдельный сборщик `collect` сохраняет результаты только
в базе Комбайна.

Синтетические карточки находятся **отдельно**:
`/home/lavkasp/lavka-speciy.com/review-factory-private-test/synthetic-reviews.sqlite3`.
В ней нет очереди публикации, ссылок на реальные review_id и доступа к MySQL.
Файл создаётся с правами 0600, в закрытой папке; каталог не публиковать.

## Резервная копия и перенос

Согласованная резервная копия включает обе SQLite через `VACUUM INTO` и
существующий `instance.json`, исключает активные сессии:

```bash
/usr/local/php82/bin/php review-factory/php/bin/console.php backup \
  --data /home/lavkasp/lavka-speciy.com/review-factory-private-test \
  --destination /home/lavkasp/lavka-speciy.com/review-factory-backup-YYYYMMDD
```

Укажите новую папку назначения. Не копировать один SQLite-файл во время работы
без учёта WAL. При физическом переносе TEST-установки переносить обе базы.
При переносе на рабочий сайт синтетическая база **не импортируется**;
генератор дополнительно блокируется по окружению и адресам установки.
См. [MIGRATION.md](MIGRATION.md). Старые ручные сценарии сохранены отдельно
в [LEGACY.md](LEGACY.md), они не являются основным сценарием текущего TEST.

Требования: PHP 7.3 для веба, PHP 8.2 CLI, PDO SQLite, mbstring; исходные
тариф, версия магазина и подключение аналитики сохраняются.

## Проверки

`php/tests/simulation.php` проверяет изоляцию базы, сохранение и неизменность
автополей, конфликты версий, владение карточкой, доли групп, баланс оценок,
распределение дат, блокировку production и отсутствие переноса модельных данных.
`php/tests/simulation_browser.py` проверяет сценарий после входа, автоматический
текст, перезагрузку, следующий товар, историю, экранирование, CSRF и 390/1440 px.
`php/tests/monitoring.php` дополнительно проверяет импорт подтверждений только
для правильных товаров, неизменность исходной SQLite, снятие соответствий,
смену URL без наследования чужих счётчиков, обработку блокировки и сбор через
подставной транспорт. Используются только локальные синтетические фикстуры.
