# 5. Условная очистка старой CSS-вставки

## Применять только при наличии этого фрагмента

На тестовой копии настройки темы загружались из JSON колонки data таблицы
с суффиксом `uni_setting`. Старый блок находился внутри `user_css`.
В рабочей установке администратор сначала определяет фактические БД, префикс
таблицы, store_id и источник настроек. Тестовые значения не подставлять вслепую.

Образцы в database/ показывают только ранее проверенный пользовательский CSS:

- `user-css-before.css` — 1240 декодированных UTF-8 байт.
- `user-css-after.css` — 301 байт сохранённых полезных стилей.
- `legacy-grid-css.patch` — точный diff до/после.
- `change-spec.json` — область изменения и хеши, без данных подключения.

## Точная операция

Найти комментарий:

```css
/* Две карточки в категориях по штатной настройке UniShop2 */
```

В проверенном исходнике за ним находится один конечный `@media (max-width:
519.98px)` с селекторами `#content[data-lavka-mobile-grid="2"]`. Удалить этот
комментарий и ровно следующий блок, сопоставив его с diff. Сохранить предыдущие
стили статьи, слайдера и `.product-page__eur-price`, а также любые иные актуальные
правки рабочего магазина. Если блок отсутствует — изменение БД пропустить.
При другом коде рядом или нескольких вхождениях объединить вручную.

`user_js` не менять: в переданной версии он выбирает первую radio-фасовку.
Если в рабочем user_js остались прежние адаптеры карточек, dropdown/counter
или широкие MutationObserver, их требуется отдельно проверить на конфликт:
эта поставка не содержит универсального удаления неизвестного JavaScript.

## Сохранение и конкурирующие изменения

- Вне публичного каталога сохранить исходное значение только меняемого поля
  и идентификаторы источника. Значения лицензии/остальных настроек в пакет
  или переписку не передавать.
- UniShop2 выводит `html_entity_decode(..., ENT_QUOTES, 'UTF-8')`; образцы уже
  декодированы. В БД поле может содержать `&quot;`/`&gt;`, а вся строка — JSON.
  Не выполнять REPLACE по всей таблице и не копировать весь JSON с теста.
- Изменить только user_css, сохраняя остальные поля. Не превращать `{}` в `[]`
  и не переокруглять числа при случайной пересериализации всего JSON.
- При записи сравнить исходное значение/строку с только что прочитанным
  через параметры и BINARY compare-and-swap; при расхождении перечитать и
  повторить ручное объединение, не затирать чужое изменение.
- Конкретный механизм сохранения выбирает администратор после проверки схемы
  и версии БД. Исполняемого UPDATE без известного источника в пакете нет.

После изменения инвалидировать кэш настроек текущего магазина и его
`generated-user-style.<store_id>.css` штатным способом. Для файлового адаптера
это соответствующие ключи `unishop.settings.<store_id>` под фактическим
DIR_CACHE; при Redis/другом адаптере использовать его механизм с тем же ключом.
Подтвердить область ключа/хранилища до очистки. Сохранить исходный generated CSS
перед удалением для сверки; не редактировать его вместо исходного поля.

Обновить также относящиеся к нему объединённые CSS/page cache по 02_INSTALL.md.
Не восстанавливать кэш всех настроек из старого снимка при откате одного поля.

Схема БД, товары, опции, цены и заказы этим изменением не затрагиваются.
