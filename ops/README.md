# Перенос каталогов существующего TEST

Команда — `python3 ops/relocate_hosting.py --plan`, затем
`python3 ops/relocate_hosting.py --apply --writers-stopped`.
Полные команды обновления обоих клонов, расписания и откат —
[HOSTING_MIGRATION.md](../HOSTING_MIGRATION.md#готовая-команда-переноса).
Сначала прочитать [HOSTING_PATHS.md](../HOSTING_PATHS.md).

Утилита работает только с `/home/lavkasp/lavka-speciy.com`; у CLI нет флага
произвольного корня/каталога данных. Python 3.6+, стандартная библиотека;
SQLite обрабатывает уже имеющийся `/usr/local/php82/bin/php`, без загрузки
приложений, MySQL, установки схем или сброса учётных записей.

План не пишет на диск и не открывает БД. Применение требует остановки
пользовательских записей и всех cron модулей, сохраняет полную закрытую копию
приватных каталогов, временно закрывает только TEST-входы, проверяет SQLite,
файлы и права магазина, затем перемещает каталоги и точечно исправляет пути.
Рабочие `www`, `lavka_storage`, их конфиги и MySQL остаются на местах.

Среди исправляемых файлов — существующий
`analytics-private-test/before-sandbox-launcher.php`: штатное обновление
проверяет его на соответствие текущему пути приложения/прежней базы.
Изменяются только эти два литерала путей; исходник остаётся в закрытой
предварительной копии. Исторические backup-каталоги не переписываются.

Журнал и полная копия находятся на хостинге в закрытой
`ops/relocations/JOURNAL_ID/`. Не добавлять их в Git и не передавать в чат.
Обычная ошибка возвращает прежние каталоги/конфиги. После обрыва процесса
использовать `--rollback JOURNAL_ID --writers-stopped`. Откат использует
актуальные данные, а не старые резервные БД. Обновлённые после переноса конфиги
автоматически не перезаписываются: потребуется проверка их изменений.

Утилита не управляет заданиями панели ADM.TOOLS, DNS и FTP/SSH.
После `completed` проверить входы и новые пути cron перед возобновлением задач.

Локальные проверки, только синтетические данные во временных каталогах:

```bash
python3 -m unittest discover -s ops/tests -p 'test_relocate_hosting.py' -v
php ops/tests/relocation_sqlite_check.php
```

Дополнительный локальный тест PHP 8.2 в уже подготовленном Docker-образе
`lavka-php-dev`: `LAVKA_RELOCATION_PHP_DOCKER=1` для Python-набора выше.
Docker на хостинге не нужен. Python-тесты используют инъекцию SQLite-проверки
только как тестовый интерфейс; CLI всегда выбирает штатный PHP 8.2.
